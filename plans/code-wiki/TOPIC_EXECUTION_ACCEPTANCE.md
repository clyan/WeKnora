# 主题分析与并发验收

实施变更：`rebuild-frontend-wiki-source-facts`。以下区分自动化检查与用户真实模型验收；不运行真实模型、不自动发布、不清理已有知识库。

## 当前实现

新任务冻结主题协议版本、来源政策、解析器、模型容量和单库并发数（默认 3，范围 1–8）。入口完成发现后退出共享 Wiki 工作池；主题使用同一队列独立认领，每次执行一个有界分析动作并保存检查点。继续任务复用原主题，不重新扫描已经规划好的目录。主题结果通过尝试身份、租约和修订号检查后单独暂存，汇总从持久状态计算。

上下文只包含当前主题、局部分析项、分页证据位置及最近一次工具结果。源码按最多 80 行读取，保留长函数作用域和条件信息；共享缓存只保存同授权范围、快照、政策和内容指纹的解析结果。未知模型容量采用 32K 的保守预算，加输出预留、工具余量和估算安全余量；超限暂停，不自动反复发送同一超限请求。

正文必须覆盖所有已登记的已查明项并引用对应依据；未完成问题阻止成文，未知与未支持情况单列。覆盖检查只对已发现项成立，不能证明模型已经发现全仓所有操作。

分析中可新增、拆分或合并主题，必须先阅读新范围的实现锚点。拆分必须为全部原分析项指定去向；合并保留双方原结论、依据和分析修订。目录、候选、发布白名单与检查点在同一事务中更新；执行中的其他来源主题或变化的修订会阻止调整。原主题以历史记录保留，原已发布正文不自动删除。目录调整后派生概览失效，等待新主题结束再汇总。

两个主题对同一个源码节点的结论或条件描述不一致时，后提交的主题增加补查问题，保留双方证据，不以最后写入覆盖。该检查提示的是需要核对的文字差异，不能自动证明语义矛盾，也不能发现所有跨节点冲突。关系查询仅提供授权快照内的源码位置候选；必须回读调用双方，索引不支持时明确转为搜索和阅读，有限结果不能证明没有调用者。

普通 Wiki 和 Code Wiki 共用 `tasklease` 执行租约生命周期：认领后统一续租，失去占用时取消执行，停止时等待续租退出，再释放自己的占用。普通 Wiki 的单库并发槽、页面锁和汇总锁使用 Redis 所有者令牌；Lite 使用进程内占用。Code Wiki 的主题认领仍由仓储事务校验任务轮次、尝试身份和修订，检查点事务负责释放。两类任务继续使用共享 Wiki 工作池，各自保留原有并发配置，不把 Map/Reduce 参数用于主题执行。普通 Wiki 初始获取页面锁或并发槽遇到 Redis 故障时保留原有降级行为，汇总锁仍拒绝执行；已取得的租约续租失败后停止工作。

主题结束后，从已接受的结论和源码依据汇总概览与导读，带回原主题及分析修订，明确摘录范围、失败和待澄清项；不再进行一次独立的全仓模型分析。失败主题重试时，派生概览失效并重新汇总，成功的原专题保留。全部主题均无已查明结论时，概览明确失败，不输出虚假的完整总览。

运行、主题、候选及事件从同一数据库快照读取，进度修订随内容变化；主题列表 API 支持状态筛选与分页，旧游标遇到进度变化返回刷新提示。主题详情按分析项、证据和人工记录分别分页。前端分别防护列表与详情的乱序响应，展开内容随对应修订更新，分页时不拼接两个版本。

前端轮询只保留最近一页事件，查看更早记录使用独立的固定页，可随时返回最新记录。旧页不会被轮询打断，也不会因长任务持续累积事件或无限补拉历史。主题详情展示原分析来源、范围调整前后身份及需要对照的记录。

复核入口将人工解释、纠错建议和样本记录与主题分析修订关联，保存用户和时间，不直接修改代码结论。阅读源码、查询进度和记录复核均不发起生成模型调用。

## 升级与降级

规划范围现在在模型调用前写入任务检查点，并随已授权的任务详情返回仓库、模块和文件路径；前端提供默认折叠的“本批规划范围”。同一批轮询保留展开状态，换批次或任务默认折叠，刷新恢复最近批次，完成后标注“最近一批规划范围”；旧任务无记录时不展示虚构内容。后端检查覆盖调用前保存、保存失败不调用模型、刷新恢复和快照隔离；浏览器组件检查覆盖默认折叠、展开、轮询保持、完成文案和换批重新折叠。前端类型检查及四种语言键和消息语法检查通过；这些检查没有重启后端或触发真实模型生成。
