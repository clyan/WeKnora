# Code Wiki 页面交互重构计划

日期：2026-10-24。状态：首批交互已实施，完整验收尚未完成；详见 [实施进展](EXECUTION_STATUS.md)。HTML 仅用于确认交互。

本计划细化 [总体实施计划](CODE_WIKI_EVOLUTION_PLAN.md) 的页面部分。Code Wiki 面向技术人员；目录以 [固定目录规范](CODE_WIKI_DOCUMENT_STRUCTURE.md) 为准。业务知识库与飞书补充另行建设。

## 1. 页面结构与入口

保留知识库现有“源文件 / Wiki / 知识图谱”三个标签。已有已发布内容时默认进入 Wiki；首次无内容时展示连接代码源、同步、生成的引导。生成期间仍可阅读上一版已发布内容。

| 区域 | 展示内容 | 主要操作 |
| --- | --- | --- |
| 源文件 | GitLab 来源、仓库角色、分支、同步状态、已发布与待分析版本、生成任务卡片 | 管理来源、同步、检查更新、查看任务 |
| Wiki | 固定目录、文档正文、代码引用、页面入口与关联功能链路 | 阅读、查证、编辑、查看版本、查看更新 |
| 知识图谱 | 文档及文档关系，明确关系类型 | 定位关联文档、跳转 Wiki |
| 页面级轻量状态入口 | 当前阶段、已完成数量、失败或待审阅提示 | 打开进度抽屉 |

知识图谱不承诺展示未经验证的代码调用图。生成管理从阅读区移出，避免顶部堆叠配置、仓库表格和完整任务列表。

## 2. 配置复用

从知识库现有设置入口打开抽屉，复用 GitLab 同步源连接与凭据管理；源文件中的“管理来源”进入同一配置位置，不新增独立设置页面。

- 连接层管理 GitLab 地址与凭据；仓库绑定层管理所选仓库、前后端等角色、分支、包含/排除目录。
- UI 可在同一抽屉内完成配置，但仓库绑定只保留一个服务端事实来源，避免同步源和 Code Wiki 各维护一份冲突的仓库清单。
- 分支可编辑。保存前展示旧分支与新分支，并说明会检查联合影响；保存配置不等于文档已更新。
- 每个仓库区分“配置分支”“最新同步 commit”“已发布文档对应 commit”。前后端都可变化，不能只显示一个知识库总分支。
- 复用已有 Provider 配置能力，作为配置中的高级选项；展示真实可用状态，不把尚未实现的分析能力显示为已启用。

实施涉及现有 `DataSourceEditorDialog.vue`、`DataSourceSettings.vue`、`CodeWikiRepositoryDialog.vue` 与仓库更新接口。先完成字段归属及编辑接口衔接，再调整表单，保留已有凭据权限边界。

## 3. 右侧进度抽屉

源文件任务卡片和页面级状态入口均打开同一任务抽屉。关闭抽屉、切换标签不终止任务；重新打开、刷新后从服务端恢复任务状态。

| 层次 | 必须回答的问题 | 内容 |
| --- | --- | --- |
| 任务摘要 | 这次在更新什么？ | 首次/增量、联合基线与目标版本、开始时间、状态 |
| 执行阶段 | 系统现在做什么？ | 同步、分析影响、核验证据、更新文档、校验、待审阅、发布 |
| 页面列表 | 哪些文档在处理？ | 保持不变、待核验、排队、处理中、候选完成、失败，以及各自数量 |
| 页面详情 | 当前具体卡在哪里？ | 当前章节、证据检索/正文生成/引用校验等子步骤、重试和可读错误 |
| 活动记录 | 系统最近有动作吗？ | 有意义的阶段事件与更新时间；连接状态另行标识 |

文档节点是 Wiki 页，不等同于源码文件。支持点击任务卡片、页节点进入详情，保留现有逐页状态查看能力；来源详情另外显示相关源码文件及其同步/分析状态。

阶段没有可靠分母时使用阶段名称和已处理计数，不伪造百分比。心跳不能冒充业务进展；事件断线显示“连接中断，正在恢复状态”，不能直接判任务失败。等待模型限流时显示原因及服务端提供的重试时间。

暂停操作区分“正在请求暂停”和“已暂停”，说明会在当前安全边界结束后暂停；恢复延续原任务。失败重试明确其范围和是否创建新任务，已完成工作能否复用以真实后端行为为准。未有对应服务端能力时不展示可用按钮。

## 4. 增量检查与审阅

1. 点击“检查更新”，冻结本次所有仓库的目标 commit，展示已发布联合基线到目标版本的差异。
2. 展示直接变更、跨仓库关联影响、需要核验的页面及保持不变的数量；每项影响可查看原因和代码依据。
3. 生成候选版本后，进入审阅抽屉查看新增、修改、删除及目录调整，并逐页对比章节差异。
4. 工具校验通过后才允许发布；校验失败展示具体阻断项与重新检查入口。发布成功后更新阅读内容和联合基线。

分支切换也使用上述流程。不能因某个仓库无代码变化就跳过跨端契约核验。待核验页不等于允许重写页；核验无事实变化时保持原文。

审阅区显示“不变 / 核验后不变 / 已修改”的区别，并可查看未变页保护校验结果。人工编辑冲突展示当前版本、候选版本与支持的真实处置选项，不提供后端尚未实现的自动合并或“保留两者”承诺。

发布前保持当前已发布版本可读。发布失败保留候选和错误；服务端事务结果决定最终状态，前端不能提前报成功。目录迁移须单独展示与确认，不能混入普通增量。

## 5. 阅读与定位

- 固定七类顶层目录，仓库节点按实际接入源码出现；不默认存在前后端公共库。
- 前端页面文档展示路由、入口操作和关联功能链路；功能链路返回对应入口，并串联前后端实现证据。
- 非页面触发的 API、任务、消息、命令行链路按真实入口展示，不强行绑定页面。
- 引用可定位仓库、固定 commit、文件及行号；失效或尚未核验的引用必须明确标识。
- 候选内容与已发布内容明确区分。未生成、无变更、生成失败、无权限、来源失联分别提供对应状态和下一步操作。

## 6. 组件与接口依赖

复用 `WikiBrowser.vue` 和 `WikiRevisionDrawer.vue` 的阅读、版本与差异能力；重组 `CodeWikiPanel.vue` 的任务、来源与配置区域，避免重复实现正文阅读器。标签切换时卸载面板不能导致全局任务状态丢失。

服务端需补齐任务及页面子步骤、带顺序号的活动事件、更新时间、等待原因、联合版本清单、影响解释、校验结果和发布结果。事件通道可采用项目适合的推送方式，并保留状态快照接口用于首次载入、重连和轮询降级；相同事件不得重复累加计数。

原有候选页及引用接口继续复用。页面动作是否可用由服务端状态和权限决定；前端禁用按钮不能替代服务端并发及版本校验。接口字段属于本计划要求，实施前与总体计划的数据契约统一。

## 7. 实施顺序与工具验收

| 阶段 | 交付 | 工具验收 |
| --- | --- | --- |
| UI-1 布局收敛 | 三标签、来源卡片、统一配置抽屉、独立任务入口 | 浏览器检查入口路径、旧能力可达性、窄屏布局及键盘焦点 |
| UI-2 可见进度 | 服务端进度事件、页面详情、恢复与重连 | 接口检查状态转换；浏览器验证切换标签、关闭重开、刷新、断线恢复 |
| UI-3 联合增量审阅 | 双分支版本、影响说明、候选差异、发布门禁 | 前后端分别变化和同时变化的端到端场景；校验失败不得发布 |
| UI-4 阅读导航 | 固定目录、入口/链路双向导航、引用定位 | 自动检查目录与链接；浏览器验证页面→链路→代码证据路径 |

所有阶段覆盖首次无内容、已有版本生成中、部分页失败、限流等待、暂停请求、人工冲突、发布失败等状态。抽屉支持键盘操作、焦点恢复、长列表滚动；窄屏改为适配宽度的面板，避免正文和操作溢出。

稳定增量必须使用真实后端多轮验证：无变化、仅前端、仅后端、双端变更、分支切换、删除或重命名、重复执行。以页面正文哈希、目录/版本及实际发布写集确认未变页未被修改；界面截图和模拟接口演示不能替代这项验收。
