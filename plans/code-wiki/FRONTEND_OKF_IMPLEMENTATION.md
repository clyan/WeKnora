# 前端代码知识库实施计划

日期：2026-10-25。采用页面、接口调用、组件与架构分层的前端知识组织方式，以及 OKF v0.2 格式。产品文案、提示词和配置使用中性命名。

## 本轮重新设计的依据

撤销“目录名称决定知识类型”和“用户设置总条目数”两项设计。不同仓库的技术栈、目录和业务组织方式不同，路径只能用来定位真实来源；文件数也不等于知识条目数。系统应负责完整列出授权快照中的文件、控制上下文、验证证据和保存进度，模型负责按需阅读、理解项目并提出知识主题。

当前流程：冻结快照 → 完整文件清单 → 模型循环列文件 / 搜索 / 读源码 / 记录项目理解 → 分页规划主题 → 校验来源与每批处理说明 → 持久化完整目录 → 逐主题生成与引用验证 → 审阅发布 → OKF 导出。

模型规划可以多文件组成一个主题、单文件拆成多个主题，也可以不采用没有证据的知识类型。系统保留知识类型参考与展示分组，不预填空章节。模型排除某文件或暂不支持时必须给出原因，决定随任务保存；未支持范围进入执行记录和生成约束。

## 阶段一：前端模板与可交换知识（本次实施）

- 代码知识库以“前端代码知识目录”为当前建设方向，不保留通用项目模板作为新流程的后备。
- 首次选择自动填充提取和内容要求；已有文本通过确认后替换，支持恢复模板默认值。设置保存模板标识，运行冻结模板及目录版本。
- 前端目录：页面模块、API模块、组件文档、架构总览（含 flows）、规范、references、待澄清问题。具体页面必须有现有源码锚点，不创建无证据内容。
- 页面、API、组件、流程分别约束内容结构；明确 API 是前端调用视角，禁止推断后端、不可访问依赖和服务端权限。
- 标准 OKF Markdown 导出：type、标题、摘要、来源、生成记录、当前发布状态；根/分组 index.md、log.md、文档间链接。仅导出已发布知识，草稿不进入知识包；log 只陈述当前版本记录，不伪造完整历史。元数据由程序生成，不相信模型生成的来源或验证声明。
- 延续快照、引用验证、审核发布、人工修改保护。旧七类目录只允许历史任务读取/恢复，不再用于新任务；不兼容的旧发布基线明确拒绝混合生成。
- 文件清单不按 pages/services 等目录名称分类。模型通过受控的文件列表、代码搜索、源码阅读和已有主题查询来理解实际仓库；所有主题必须关联真实且已阅读的源码，引用区间必须来自实际阅读记录。
- 文件清单自动按上下文分页处理，没有 60/200 条总文档限制，也不要求用户调整条目预算。每批必须逐文件说明已形成知识、无关或未支持，遗漏文件则不能结束该批。分页只是上下文管理，不代表语义覆盖率。
- 规划笔记、阅读区间、已接受主题、文件处理说明和游标保存在任务配置检查点中；逐条生成使用持久化待处理列表。模型调用安全额度用完或超时会暂停保留进度，继续时取得新的执行额度并保留累计消耗，不能跳过剩余文档进入等待发布。
- 完整规划与目录落库完成标记单独保存，防止规划暂停或写入中断被误认为完整目录。增量任务在完整规划前不能进入影响范围审批。规划失败不回退生成泛化章节。

验收：默认要求保存往返、目录类型/锚点/稳定标识校验、无后端情况下生成规则、禁止旧目录混入新任务、OKF YAML/链接/路径安全/来源及版本可追溯，Go 定向测试、前端类型检查与构建。

## 阶段二：知识清单和分析覆盖

- 从全量文件清单和解析结果建立页面、操作、API、组件任务清单；区分已发现、待分析、完成、待澄清和不支持。
- 持久化对象与类型关系、API 使用方反向索引，关联路由/操作/调用点，按任务保存断点。
- 分批覆盖和预算治理，显示实际分析范围，不能将本轮页数限制解释为全库完整覆盖。

验收：选取真实页面操作，能够定位接口调用与状态变化；中断后恢复；新增源码生成新条目，避免重复。

## 阶段三：补充材料、后端与业务派生

- 接入接口说明和后端仓库；沿用前端条目标识，补全关联并记录需求/前端/后端差异。
- 业务知识引用已发布代码知识版本，同时接入需求与人工确认资料；来源变更标记待复核。
- 权限沿来源约束，人工确认后发布；角色视图和 Skills 在此后扩展。

## 范围与兼容

OKF 是知识表示和交换格式，不代替现有数据库、权限或代码分析器。第一阶段数据库正文继续为可阅读 Markdown，导出时生成规范元数据及链接。OKF 核心格式可用，不意味着已经完整分析全部前端或实现完整 v0.2 消费器。旧模板、自由目录和泛化后备不属于新流程的兼容目标。

### 第一阶段明确限制

- 主题粒度由模型根据证据决定，支持独立接口、流程和问题条目，但尚未建立解析器驱动的完整路由/接口注册表、类型关系数据库或全调用图；不能保证模型没有漏判或误判语义。
- 文件清单全量分页处理，模型按需阅读；“清单已检视”不代表所有文件已完整阅读，更不代表业务语义已经验证。排除说明也是模型判断，需要真实项目审阅验证。
- 规划与生成均可恢复。内部调用额度或执行时间达到边界时，需使用现有“继续”操作恢复；尚未实现自动跨后台队列续期或费用确认流程。
- 正文证据使用有界片段与搜索结果；未查看的代码、动态行为和不可访问依赖不能视为已验证。代码引用校验不代表业务语义或运行时验证，因此 OKF 不自动填入 verified。
- OKF 导出是知识的可交换表示，平台正文仍为 Markdown；完整 OKF 导入/消费器、语义类型关系及业务派生尚未实施。

### 本轮验证

自动化测试覆盖非标准目录、多个源码组成一个主题、单文件多个主题、201 个主题不受旧页数设置限制、跨文件清单批次继续、规划检查点序列化恢复、晚于第 500 行的真实证据、虚构/未阅读来源拒绝、遗漏清单文件拒绝，以及无效模型输出不会退回通用目录。真实模型生成质量与真实仓库全流程仍待验收。
