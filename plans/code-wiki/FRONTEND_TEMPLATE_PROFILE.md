# 前端模板采用说明

以《代码 Wiki 知识库方案》的前端模板（5.4～5.16）作为正文组织基础，接入现有代码知识生成流程。模板仅定义文档要求，不代表已完成真实仓库的全量分析或运行验证。

## 与现有知识分类的映射

| 方案主题 | 当前分类 | 组织方式 |
|---|---|---|
| 页面 | frontend_page | 默认一页面一篇；多个路由复用时保留入口差异 |
| API | frontend_api | 默认一请求模块一篇，函数清单后逐接口展开；复杂模块可拆分 |
| 组件 | frontend_component | 默认一组件一篇，保留实际使用方 |
| 前端业务流程 | frontend_workflow | 有调用/事件依据的操作链，保留并行、分支与断点 |
| 主子应用、通信、技术栈、基础设施、跨仓依赖 | frontend_architecture | 按实际主题选择专用结构，一篇一主题，不强制生成所有主题 |
| 规范 | frontend_convention | 当前仅核对配置、执行入口与观察到的实现模式 |
| 组件文档总览、反向关系 | frontend_reference | 有现成文档及关系记录时汇总，不伪造工具统计 |
| 未知项 | frontend_question / 各篇待确认 | 记录缺证原因、范围和补证需求 |

保留当前分类标识与目录版本；不把方案里的细分 type 直接作为新分类注册，也不迁移已有页面。导出元数据仍由服务端生成，正文模板不让模型填充 YAML。

## 补齐的取证要求

- API 参数区分类型声明、定义侧请求构造、调用点真实传入；追踪对象构造、展开覆盖、默认值、条件转换与封装追加字段。无调用点仍可收录定义，不能断言全项目无人使用。
- 页面保留操作清单、接口、权限降级、页面跳转、组件协作、状态读写、微前端与异常分支。
- 组件保留必填属性、事件载荷和接收方、暴露方法、插槽、内部接口与实际使用位置。
- 架构区分依赖声明、锁定版本、实际使用和环境生效；不从普通包集成推断微前端。
- 后端链接必须有请求方法、路径、服务归属和必要的网关映射依据；不得编造未接入的后端文档。
- 不生成虚构的 owner、last_verified、confidence 或全量覆盖声明；未统计页面数不能填零。

## 现有能力边界

方案中的规范原文汇总需要文档来源及审核机制，当前源码事实策略仍排除文档、注释和 Mock 作为业务实现证据。本次没有放宽该策略。

组件总览与反向关系章节只消费已提供且有权访问的文档和关系，不新增独立的 views 分类或自动索引生成器。前后端双向挂接、人工经验入库、独立元数据字段和生命周期治理不因模板更新而自动具备。

运行配置中的提取/内容要求由已有配置快照保存；新默认值不会追溯改写已保存的用户设置、运行快照或已发布正文。
