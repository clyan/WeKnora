# Code Wiki 后续实施计划：交互、固定目录与稳定增量

日期：2026-10-24。状态：已开始分阶段实施，尚未完成；实际交付与验证见 [实施进展](EXECUTION_STATUS.md)。面向技术人员的 Code Wiki 是本轮主体，业务知识库作为后续独立阶段。

本文收敛本次讨论，并作为后续新增工作的执行顺序；既有实现背景和首版验证项见 [原实施计划](../../docs/CODE_WIKI_IMPLEMENTATION_PLAN.md)，目录契约见 [固定目录规范 v1](CODE_WIKI_DOCUMENT_STRUCTURE.md)。此前探索性方案与本文冲突时，以本文及固定目录规范为准。HTML 是交互示例，不代表能力已上线。

## 1. 已确认边界

1. **技术与业务分开**：Code Wiki 只服务技术人员，后续另建业务知识库，输入为飞书文档与选定的已发布 Code Wiki。
2. **只分析已提供源码的仓库**：必须明确绑定、授权且进入本轮冻结清单。未提供源码的第三方依赖不抓取、不查内部源码、不推断内部实现。
3. **前后端联合分析**：两侧均可能更新或切换分支，分别比较变化，再联合判断接口、功能链路和文档影响；不能只重生成变化仓库的说明。
4. **延续现有交互**：保留“源文件 / Wiki / 知识图谱”；GitLab 连接与仓库范围复用同步源入口；任务卡片/轻量状态打开右侧抽屉；生成设置复用已有 Wiki 设置。
5. **固定目录与页面身份**：顶层七类固定，仓库与功能实例按源码展开。功能链路关联页面、API、任务等实际入口，关系为多对多。
6. **稳定性是发布约束**：增量更新不得改写未受影响页面，不能每轮重新规划目录或大范围润色正文。工具校验失败时不得发布。

“未提供源码的第三方依赖”仅允许从已提供代码记录依赖声明、版本、使用位置、参数组装、返回值处理和异常处理；链路到此边界停止。外部服务内部流程保留未知。独立依赖库只有源码也被明确接入时，才作为普通参与仓库分析，不是默认必选角色。

## 2. 现状与新增工作的区分

| 范围 | 已有基础 | 本计划新增 |
| --- | --- | --- |
| 输入 | GitLab 连接、多仓库绑定、固定快照、可替换分析服务 | 同步源内统一配置、完整分支编辑、配置/活动任务版本分离 |
| 生成 | 模型规划、逐页生成、引用校验、候选、发布及人工保护相关代码 | 固定目录执行、稳定页面/章节、结构化事实、最小更新与发布前防漂移校验 |
| 进度 | 阶段文字、页数、轮询及暂停/继续 | 页内步骤、活动记录、等待/断连/暂停请求、跨标签持续观察 |
| 增量 | 可复用快照与分析产物；现有文档描述为全量生成 | 前后端联合 diff、影响集合、仅更新相关内容、多轮稳定性验证 |
| 业务 | 已有文档同步与 Wiki 能力可复用 | 独立业务知识库关联、业务说明生成和来源更新传播 |

这不是完整运行验收结论。原计划阶段 0 的引擎/隔离验证与阶段 4 的部署可靠性验收仍需完成；已有函数不等于所有目标行为均已验收。

## 3. 增量更新的硬约束

### 3.1 先区分三种变化

- **源码变化**：某个仓库的文件、接口、符号、配置或依赖声明变化，不代表所有文档都要更新。
- **文档事实变化**：源码变化使某页描述的能力、链路、契约、入口或限制需要改变。源码本身未变的页面也可能因另一仓库变化而受影响。
- **表达变化**：事实未变，仅模型措辞、标题、段落顺序不同。普通增量禁止此类更新。

“未变更页面”定义为：自身事实及关联影响经检查未变化的页面，而不是“所属仓库没变”或“旧引用文件没变”。前端调用变化可影响后端契约/联合链路，反之亦然。

### 3.2 原样保留

不在已批准影响集合中的页面：

- 正文按原始字节保留，不重排列表、不调整空白、不重新摘要、不调用模型润色。
- 标题、slug、目录父节点、排序、页面 ID、章节锚点、内部链接及页面版本保留。
- 原有代码证据及历史快照引用保留；不得统一改成最新 commit。
- 不执行页面更新写入，不生成无意义修订或页面更新时间。
- 可以在独立的本轮复核记录中说明已检查/沿用，不回写页面正文或旧证据。

无源码、范围及有效配置变化时，返回“无须更新”，页面生成模型调用为零，发布修订为零。仅分支名称变化但解析到相同 commit，记录跟踪配置变化，不因此重写技术文档。版本清单与任务记录可独立更新，不能借更新日期改写所有页面。

### 3.3 影响集合是写入白名单

生成前持久化计划：`保留 / 更新 / 新增 / 移动或改名 / 废弃 / 仅复核`。每项记录原因、变化文件/符号、传播路径、允许更新的章节和证据。

模型只能提交候选补丁，不能直接改正式 Wiki。更新集合外出现任何页面/目录写入，服务端拒绝。新增、移动、改名、废弃是独立结构操作，不能通过换标题或换 slug 冒充正常更新。

生成中发现新的必要影响时，先修订计划并补工具依据，再扩大白名单；不能自行写入范围外页面。普通内容更新不允许任意移动/合并文档。

### 3.4 受影响页面也尽量局部更新

模型读取旧正文、允许变更的事实、相关源码与章节标识，仅提出指定章节的替换/插入/删除。补丁带预期页面版本、旧片段/章节 hash；不匹配时进入冲突，不能模糊匹配后覆盖。

章节外字节保留；新的代码引用由服务端校验并维护。只有结构性事实变化确实影响全页时，才在计划中记录全页重生成理由，并进入差异审阅。不能以“提高质量”默认重写整页。

允许范围内的候选若与原文完全相同，转为沿用，不增加页面版本。低温度、固定提示词或二次模型审稿不能替代这些约束。

## 4. 版本、目录和事实基线

### 4.1 联合代码基线

每个发布版本关联完整仓库清单：稳定仓库 ID、角色、跟踪分支、commit、过滤配置、快照/分析产物版本。以前次成功发布清单为基线，冻结本轮所有目标 commit，再分别比较 F0→F1、B0→B1 及其他已接入仓库。

源码归档可能不含 Git 历史：优先使用受限 Git diff 或 GitLab 比较能力；不可用时比较两份授权快照的路径/文件 hash，得到新增、修改和删除。重命名检测只是候选，需核验内容与符号对应。不能假设非祖先分支一定可按提交列表可靠比较；净文件差异可用时仍可分析。

最近同步、未发布候选和失败批次不改变成功发布基线。仅文档发布成功也不意味着对应代码已经部署；客户在用版本需有单独确认的版本清单。

### 4.2 页面与章节基线

保存固定目录规范版本、目录/页面稳定 ID、父节点、排序、标题、slug、正文原始 hash、章节 ID/hash、页面版本、人工编辑来源、证据引用及页面关联。

页面身份不由 commit、标题或行号决定。排序持久化；模型返回数组、map 遍历顺序不能决定最终目录。新增页面插入指定位置，不重新排列已有页面。目录规范升级与旧分类迁移为独立操作，不在普通增量中自动发生。

### 4.3 可定位事实与关联

为接口签名、页面路由/操作、服务入口、关键状态/规则、配置使用和外部调用建立结构化事实及源码证据；保存“事实 → 章节/页面”“入口 → 功能链路”“接口调用 → 处理端”等映射。

工具可确定的字段尽量由解析/检索与源码核验获得。模型用于主题归纳和解释，不能单独确认关系。事实 hash 采用固定字段与排序的规范化表示，正文保护仍用原始字节 hash；语义 hash 相同不意味着可以忽略文件/路由/注释等其他有效变化。

对复用页记录目标清单下的复核状态，与该页原始证据版本分开。人工保留或失败页不能被标记为已更新到新代码版本。

## 5. 联合影响分析流程

1. 校验权限、仓库源码可用性、快照身份和分析服务能力，冻结输入与目录/生成规则版本。
2. 比较所有参与仓库的净文件变化；同时识别过滤、分析服务、目录规范和生成规则变化，不能把这些变化当成普通无代码变化。
3. 提取变化符号、路由、接口、类型、状态、入口、配置和依赖声明；新功能不能只靠旧引用发现。
4. 从变化事实向入口、调用/依赖、跨仓库接口与页面/章节映射传播。变化一侧与未变化一侧一起核验，范围不超出已提供源码仓库。
5. 从变化前与变化后的关系共同追踪，捕获已删除或重命名的入口、边及契约，避免只看新图漏掉旧关系受影响页面。
6. 记录直接/间接影响和原因，生成写入白名单；没有事实变化的页沿用。
7. 生成局部候选、执行工具校验，展示差异，确认后事务发布。

图查询必须检查覆盖、版本、分页和截断。静态图只能产生候选；跨端匹配核验方法、路径、baseURL、代理重写、服务身份与源码上下文，不能靠同名猜测。

关系覆盖不足时扩大检索与源码核验范围；仍不可靠时执行全范围影响分析。**全范围分析不等于整库重写**：仍然比较旧事实与候选，保留无须改变的目录/正文。影响结论无法可靠确认时，阻止自动发布并给出待核验项；不能把重新生成整库当成消除不确定性的办法。

## 6. 工具校验清单与发布门禁

以下均为待实现的程序化检查。优先复用现有 Provider、快照读取和引用校验能力，缺失时增加适配；不假定每个 Provider 都有完整 AST 或跨仓库图。

| 检查 | 工具/程序依据 | 失败处理 |
| --- | --- | --- |
| 输入身份与范围 | 授权校验、冻结清单、固定 SHA、快照/过滤 hash | 阻止任务或要求明确排除，不静默遗漏 |
| 代码变化 | Git/GitLab 比较或快照文件 hash 比较，记录策略与完整性 | 更换可用比较方式；仍无法比较则不发布可靠增量结论 |
| 结构与关系 | 路由/类型/符号解析、图查询、调用追踪、覆盖与分页检查 | 有缺口则定向读源码；无法确认保留未知 |
| 源码证据 | 固定快照内文件/行号/符号/片段校验，双端关系核验 | 引用无效或关键结论无依据时阻止对应候选发布 |
| 目录合法性 | 固定 schema、唯一稳定 ID/slug、父节点与排序快照、合法变更操作 | 任意新增顶层分类、无授权改名/移动/重排均拒绝 |
| 写入范围 | 实际候选/数据库写集与影响白名单逐项比较 | 任意越界即阻止整轮发布 |
| 未变页面保护 | 正文原始 hash、标题/路径/排序/锚点、版本、原证据清单比对 | 任一保护字段变化即拒绝，列出误改位置 |
| 局部补丁 | 预期版本与旧章节 hash、允许章节范围、非变更区字节比较 | 过期或越界补丁进入冲突，不自动整页覆盖 |
| 事实变化与内容差异 | 结构化事实 diff、候选文本 diff、更新原因映射 | 无依据的措辞改写退回；不可工具判定的语义结论进入审阅 |
| 引用和链接 | 代码证据、文档目标/锚点存在性、删除/重命名后的反向链接检查 | 死链或证据失效需修复；不能回指最新分支掩盖问题 |
| 重复与异常扩散 | 重复 ID/slug、相同正文 hash、目录变动数、页面/章节改动数及影响路径 | 重复拒绝；无法解释的大范围差异阻止自动发布并要求审阅 |
| 发布并发与历史 | 版本基线/乐观锁、事务、幂等键、变更前后写集审计 | 冲突不覆盖；事务失败完整回滚 |

实际发布操作再次执行范围、版本和保护字段检查，不能仅信任生成时的报告。已变页与新页的关键事实、引用均须有依据；“行号能打开”不能证明结论正确。第二个模型审稿只能辅助，不能替代确定性检查。

版本清单、统计和更新记录是独立系统记录或白名单内的派生页面：只在输入/目录/事实确实改变时更新相应字段，不能成为每轮全面改写的例外。

## 7. 服务端契约与数据变更

在现有 run、候选页、发布与证据结构上扩展，具体字段/迁移由实施阶段定稿：

- 生成批次：基线发布 ID、目标清单、配置/目录规范版本、比较策略、影响计划版本、校验报告、状态与任务进度。
- 影响项：页面/章节稳定 ID、动作、理由、变化事实、传播路径、预期版本/hash、允许的结构操作、候选补丁。
- 事实/入口关联：源码范围、固定版本、提取器版本、证据、页面关联、完整性与核验状态。
- 复核与审计：保留页目标清单复核、原证据版本、实际变更清单、校验失败、人工决定；不伪造页面已更新状态。

API 扩展为读取版本比较、影响计划、候选差异、校验结果和分页活动记录；发布携带计划版本与基线。复用现有权限和任务接口，端点命名沿用项目风格。

默认人工确认发布；失败、取消或未解决冲突不替换上版。部分发布作为显式能力单独设计，不能悄悄跳过失败页后称整轮成功；如允许部分发布，应保留每页实际状态，后续继续处理未完成的影响项。

## 8. 页面与任务抽屉

### 8.1 三个原有标签

- **源文件**：GitLab 同步源及其仓库、角色、分支、过滤和准备状态；源码树按仓库展示。
- **Wiki**：固定文档目录、阅读/编辑、版本和代码证据；轻量任务状态可随时打开同一任务。
- **知识图谱**：文档关系视图，不能冒充真实代码调用图。

连接凭据、仓库和分支在同一同步源抽屉配置，内部继续保持仓库绑定的单一事实来源，不同时维护两套项目列表。分支修改使新配置待同步，但进行中的任务继续使用冻结配置；新任务使用明确准备好的版本。生成模型、语言、指令、预算和高级分析服务复用已有 Wiki 设置。

### 8.2 可解释进度

阶段：比较版本 → 联合影响分析 → 生成/校验候选 → 差异审阅 → 发布。

抽屉展示当前页面/章节、检索/写作/校验子步骤、已校验/失败/跳过页数、最近真实活动、等待原因与可执行操作。页数只统计本次实际生成范围，不把全库页数当增量进度。

增加持久活动序号与时间、步骤起始时间、业务活动时间、worker 心跳、重试次数/计划重试时间和暂停请求状态。先提供可恢复的轮询与分页事件；事件流属于可选传输优化，不能替代持久状态。

限流展示真实重试安排；断连展示最后确认状态，不能断言后台停止；暂停请求与已暂停分开；关闭抽屉不影响任务。原始诊断按需展开，不展示或编造模型私有推理。

### 8.3 审阅

按保留、局部更新、新增、结构变动、废弃、失败与人工冲突展示。每项给出旧/新版本、影响原因、章节差异、证据与工具校验结果。无变化页面明确“沿用，未改写”。目录漂移与无依据的范围扩大是阻断项，不能隐藏在一个“生成成功”提示内。

## 9. 分阶段执行与交付

| 阶段 | 实施内容 | 完成条件 |
| --- | --- | --- |
| A：契约与稳定基线 | 固定目录、输入白名单、稳定页面/章节、原文/hash/排序基线、旧目录迁移方案 | 固定规范与样例契约可验证，现有人工页与链接有明确兼容方案 |
| B：进度与原有交互融合 | 三标签、同步源配置、任务抽屉、页内步骤、事件/心跳和暂停状态 | 长耗时步骤可观察，切标签/刷新不丢任务，不重复配置或提交 |
| C：联合影响分析，只读预演 | 全仓库净 diff、事实/入口映射、跨端核验、新增删除发现、影响计划 | 对照人工标注样例，能解释直接/间接影响与未知；不修改正式页 |
| D：稳定候选与校验 | 局部补丁、保留页复用、确定性缓存、范围/目录/正文/证据门禁、候选审阅 | 越界、无关改写与目录漂移均被程序阻断，无变化时生成调用为零 |
| E：发布与多轮回归 | 事务写集、并发人工修改、重复提交、失败恢复、连续增量回放 | 多轮稳定性与故障场景通过，误改零容忍；完成原计划部署/隔离验收 |
| F：独立业务知识库 | 飞书同步复用、已发布 Code Wiki 关联、业务说明及更新传播 | 技术/业务权限分离，业务内容只发布已确认的客户当前能力 |

依赖：A→C→D→E；B 在 A 的状态契约确定后可与 C 交错实施。F 依赖稳定的已发布页面身份与版本。Webhook、自动发布、向量检索、模板编辑器、独立代码图和自动运行项目脚本不作为本轮前置工作；后续按独立需求安排。

模型版本、生成指令或目录规范升级不得随普通增量隐式全面改写；需要专门迁移/重新验证任务和差异审阅。缓存复用必须校验输入、权限与产物完整性，不能用旧结果掩盖代码变化。

## 10. 多轮增量测试与验收

建立有已知前后端链路、定时任务、外部依赖与人工页面的固定测试仓库；离线回放每轮 commit 清单，保存目录、正文、章节、证据、版本及实际数据库写集。测试由开发阶段交付可重复运行的检查器，不能只依靠截图或模型自评。

| 场景 | 必须验证 |
| --- | --- |
| 连续多次无变化 | 页面生成调用为零；正文、目录、排序、版本和证据全不变 |
| 单侧局部变化 | 仅对应章节与经证明关联的契约/链路更新，无关页字节一致 |
| 双侧同时变化 | 合并影响且去重；发现两侧不兼容，不编造正常链路 |
| 任一侧切分支 | 比较实际 commit 净差异；分支名不产生新目录；相同 commit 不重写 |
| 新功能无旧引用 | 识别新入口/事实，按规范增加页面，已有页面不重排 |
| 删除、改名和入口移动 | 更新必要索引/链路与反向链接，历史来源可解析 |
| 声明依赖版本变化但无依赖源码 | 仅检查本项目声明与使用点，不抓取或分析第三方内部 |
| 未变化共享代码或普通工具目录 | 不创建默认依赖库，不扩大源码范围 |
| 模型措辞/顺序波动 | 不在白名单的修改被阻断；无事实变化候选不写入 |
| 一页局部修改 | 非允许章节字节一致，锚点和关联稳定 |
| 失败、取消后再次更新 | 仍以上次成功发布为基线比较净变化，不跳过未发布的代码变化 |
| 并发人工编辑 | 补丁/发布基线冲突被发现，不覆盖人工内容 |
| 缺失覆盖/截断/旧快照丢失 | 扩大验证或阻断，不能把局部结果当成完整影响结论 |
| 模型或配置升级 | 不自动整库润色；执行显式验证/迁移与审阅 |

还需做连续序列：初次发布→前端局部改动→后端接口改动→无变化→分支切换→功能新增→删除/重命名→中途失败→再次更新。各轮自动比较保留集合，任何误改都判定失败。

最终硬指标：**白名单外写入为零、未变页正文/目录/版本变动为零、无依据结构变动为零、已发布无效代码引用和死链为零**。出现问题应阻止发布，不能先发布再用后续重生成修复。

## 11. 后续业务知识库边界

技术 Code Wiki 与业务知识库独立。业务知识库复用飞书文档同步，并关联选定发布版本的 Code Wiki；先整理业务说明，再面向业务 Agent 检索，不直接把源码和技术冲突开放给业务用户。

现有系统已确认能力是业务回答基准，飞书补充术语、背景和操作说明；需求草稿不能变成已实现承诺。冲突进入维护人员待核验列表；业务侧只发布已确认说明，不主动展示内部实现差异，也不能掩盖实际操作限制或把未知说成不支持。

业务侧按客户实际使用版本生成；文档发布或开发分支更新不等于客户部署升级。源访问权限与衍生内容发布权限分别校验，关联技术知识库不自动赋予业务用户源码/原文访问权。后续记录“技术页面/飞书版本 → 业务页面”的关系，来源变化只更新相关业务说明。
