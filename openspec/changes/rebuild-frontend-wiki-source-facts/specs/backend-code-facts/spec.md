# Spec Delta

## Purpose

在后端源码已接入的范围内建立接口、调用链、数据落点和依赖的实现基线，并与前端调用建立可复核关联。缺失源码或动态分派无法解析时保留未知边界，避免把声明、命名、前端推测或模拟数据当成服务端行为。

## ADDED Requirements

### Requirement: 后端接口以注册和实现为依据

系统 SHALL 从已提供后端快照提取 HTTP 路由、方法、处理入口、参数绑定、实现中的校验及关联中间件，分别记录源码位置和条件。首批 SHALL 支持 Go；其他语言及未支持框架 SHALL 明确显示分析边界，不生成通用后端内容填补空白。

#### Scenario: 没有后端仓库
- **WHEN** 知识库只绑定前端源码
- **THEN** 系统仅描述前端调用，不生成后端已实现、已鉴权或已落库的结论

#### Scenario: 接口有路由组中间件
- **WHEN** Go 路由通过路由组注册并挂载校验中间件
- **THEN** 系统保留注册、处理器及中间件的证据关系，不只列出处理器名称

### Requirement: 调用链保留解析边界

系统 SHALL 追踪可确认的处理器、服务、仓储及外部调用，并给出每个链路节点的来源；接口分派、反射或不可访问实现不能唯一解析时 SHALL 标记候选或未知，不将其拼成确定调用链。

#### Scenario: 服务通过接口调用未知实现
- **WHEN** 处理器调用接口方法，但当前快照无法确定注入实现
- **THEN** 调用链在该接口边界明确中止或列出候选，不断言某个实现一定被调用

### Requirement: 数据落点与依赖逐项查证

系统 SHALL 根据实际数据访问代码及其映射关系描述数据库表或集合、缓存键、消息目的地、外部服务与读写动作；事务边界、条件写入和字段映射必须有实现依据。模型或依赖声明不能单独证明运行中的读写及使用关系。

#### Scenario: 有模型但没有写入链路
- **WHEN** 存在订单模型定义但未确认该接口通向保存逻辑
- **THEN** 系统记录模型声明，不宣称接口会写入订单表

### Requirement: 前后端关联保留差异

系统 SHALL 在方法、路径及可确认的前缀/代理转换一致时关联前端调用与后端入口，展示字段、校验和响应使用差异；匹配不唯一或版本不同的关系 SHALL 保持待核对。

#### Scenario: 前端字段在后端未绑定
- **WHEN** 已确认前端传入某字段，但对应后端实现没有绑定或读取该字段
- **THEN** 系统显示两侧证据及差异，不自动生成统一且虚假的接口契约
