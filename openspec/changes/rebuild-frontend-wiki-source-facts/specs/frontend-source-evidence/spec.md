# Spec Delta

## Purpose

规定前端知识可使用的来源与证据强度，使知识反映当前代码快照中可追踪的实现。排除过时说明与模拟材料对业务事实的影响，并明确静态分析、声明结构、运行结果和后端实现之间的边界。

## ADDED Requirements

### Requirement: 事实仅由当前实现支撑

系统 SHALL 仅接受冻结快照中的实现逻辑、真实使用关系及与该实现相关的配置作为事实证据。系统 MUST NOT 使用 README、已有文档、说明性注释、Mock、样例或测试断言证明当前业务行为；名称、注释或类型声明不能单独证明行为。配置声明仅证明配置内容，未确认环境选择时不能声称线上已生效。

#### Scenario: 注释和实现矛盾
- **WHEN** 注释写着需要管理员，但执行条件只判断记录状态
- **THEN** 生成内容描述实际状态条件，不得输出“仅管理员可操作”

#### Scenario: 业务只出现在旧材料中
- **WHEN** 功能只出现在文档、Mock 或测试断言中，当前实现中没有可追踪依据
- **THEN** 系统不得将其加入已确认业务能力或接口契约，可记录为无实现证据的问题

### Requirement: 声明与实际使用分别陈述

系统 SHALL 区分类型或依赖声明、已接入的组件/路由/调用关系和已追踪的条件分支；未接入实现不得被描述为可用页面，前端请求不得被描述为已经由后端实现或验证。

#### Scenario: 类型字段并未传入
- **WHEN** 请求类型含字段 currency，但调用点构造的参数未包含该字段
- **THEN** 系统将 currency 标记为声明字段，不将其列为该调用点真实发送字段

#### Scenario: npm 引入不等于微前端
- **WHEN** 应用通过包导入并挂载组件，而没有已确认的微前端加载与通信实现
- **THEN** 系统描述包集成及组件传参，不生成主子应用运行机制的事实

### Requirement: 证据身份和推断边界可追溯

每条已接受事实 SHALL 关联仓库、快照、提交、路径、行号及支持关系的证据；间接关系 SHALL 保留中间来源或明确未知节点。系统 MUST NOT 将搜索命中、图候选或合法行号等同于语义证明或线上实际执行。

#### Scenario: 跨仓库版本不同
- **WHEN** 消费方声明业务包版本 1.3.1，而提供方快照声明 1.3.0
- **THEN** 系统分别记录声明值和组件集成证据，指出版本对应关系未确认，不宣称两端运行实现一致

### Requirement: 来源政策不能被提示词放宽

系统 SHALL 冻结本次任务的来源政策版本，并在提取、正文、增量补丁及发布校验中执行相同约束。用户可修改内容偏好，但自定义提示词或源码文本 MUST NOT 将禁止来源升级为业务证据。

#### Scenario: 自定义要求相信注释
- **WHEN** 用户设置要求直接采用注释、文档或 Mock 中的字段说明
- **THEN** 系统仍只接收实现支持的事实，并提示相关要求受到来源政策约束
