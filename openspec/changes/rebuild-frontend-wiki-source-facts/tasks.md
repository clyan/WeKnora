# Tasks

按阶段执行：第 1–4 组为阶段一，第 5–6 组为阶段二，第 7–8 组为阶段三，第 9 组为后续领域阶段。每阶段完成后先交付验收结果；不得以清单勾选代替实际源码与生成质量核对。

## 1. 阶段一：来源政策与版本隔离

- [ ] 1.0 增加 project/domain 模式类型及历史默认 project，创建时选择且有数据后禁止切换；领域能力未开放时明确拒绝执行，不回退项目规划器；以配置往返、模式隔离和运行入口测试验证。
- [ ] 1.1 在运行配置、类型和默认模板中增加来源政策、事实模式与分析器版本，替换允许资料/Mock 事实的要求；验证新任务冻结版本、自定义提示词不能放宽规则、旧任务仍可查看。
- [ ] 1.2 增加文件来源资格分类与排除原因，覆盖文档、Mock、样例、测试及普通路径中的模拟实现；用非标准目录和来源歧义样例验证不会把主题分类等同于路径分类。
- [ ] 1.3 提供基于语法节点的注释过滤视图和原行号映射，将搜索、read、模型上下文及引用校验统一接入；验证过时 JSDoc/行注释、多行注释、字符串中的注释符号及晚于第 500 行的实现定位。
- [ ] 1.4 隔离旧笔记、旧索引摘要和旧正文事实输入，旧活动任务提供查看/停止及重建提示；验证不能在旧检查点恢复后混入新政策，且没有自动删除或发布。

## 2. 阶段一：事实存储与结构候选

- [ ] 2.1 增加任务级事实、证据、关系和文档映射的数据类型、仓储接口及 PostgreSQL/SQLite 迁移；以仓储集成测试验证租户隔离、幂等写入、唯一键、版本查询及旧数据兼容读取。
- [ ] 2.2 增加问题、人工解释及基础样本复核记录存储；验证人员/时间/版本留痕、权限检查及人工解释不能直接升级为代码事实。
- [ ] 2.3 封装固定版本 JS/TS/JSX/TSX 结构分析进程及健康检查，接入部署运行时；验证缺少运行时明确报错、不执行仓库脚本/配置/插件，不安装目标仓库依赖。
- [ ] 2.4 提取 import/export、JSX、调用、对象构造及控制条件候选，关联来源节点；用 React 与普通 JS/TS 样例验证声明和实际使用分离，未支持语法显式记录。
- [ ] 2.5 增加路由与请求封装能力适配入口，首批覆盖 React 路由配置及常见 request/axios/fetch 静态调用；验证非标准目录、未知封装、动态注册及不可访问依赖不会被误标完整。

## 3. 阶段一：页面操作与 API 参数追踪

- [ ] 3.1 在现有规划器前建立入口和使用关系清单，再登记按钮、菜单、行操作、表单及自动触发；用父子组件与条件渲染样例验证已发现操作都有入口和处理逻辑对应。
- [ ] 3.2 追踪显示、禁用、校验、状态、跳转、异常与加载分支并形成条件关系；验证注释写“管理员”但实现只判断状态时，不生成管理员权限结论。
- [ ] 3.3 建立接口声明与真实调用点反向索引，追踪方法、路径、前缀和封装追加字段；验证无调用者仅报告本次查找范围，不推断后端已经实现。
- [ ] 3.4 追踪调用点参数的局部赋值、对象展开、默认值、条件字段及跨文件辅助函数；用新增/编辑不同参数、同名字段覆盖顺序、未知动态键样例核对逐字段来源。
- [ ] 3.5 追踪调用方使用的响应字段与失败处理，保持类型声明与实际使用分离；验证仅类型声明字段不进入“真实传入/实际使用”列表。
- [ ] 3.6 将分析对象、已读证据、待追踪边和状态持久化为检查点；验证参数追踪期间超额暂停、进程重启和重复消息恢复不漏项、不复制、不混快照。

## 4. 阶段一：成文、基础复核与真实页面验收

- [ ] 4.1 改造正文生成协议为共享事实、条件、未知项及 section→fact 映射，停用新任务的固定片段一次成文后备；验证来源资格、引用和已发现项覆盖分别报告，十二项只写八项会阻止候选发布。
- [ ] 4.2 生成页面和 API 专题，并在相关专题之后生成概览和导读；验证两处参数说明一致、概览包含入口与分工、链接只指向已存在文档，不出现 Mock 业务说明或原始 slug 阅读指引。
- [ ] 4.3 接入事实、覆盖、问题和基础抽样复核查询/修改 API 及界面；验证用户能查看实现证据、补充人工解释、登记纠错与复核结果，且人工解释单独标注。
- [ ] 4.4 扩展任务事件及加载状态，展示分析对象、查找调用、阅读文件和暂停原因；验证执行/完成/失败/暂停图标正确、排版对齐、无凭据与内部推理泄露。
- [ ] 4.5 在关系增量尚未交付时提供明确的全范围重新分析及旧正文对比路径，沿用人工保护；验证不会标为精确增量或静默覆盖人工修改。
- [ ] 4.6 选当前可访问的一个真实 React 页面做入口、已发现操作、权限条件、调用点和字段来源对照表；完成来源反例与暂停恢复测试、相关 Go 测试、前端类型检查/构建及浏览器预览，并单列真实模型生成结果和仍未确认范围作为阶段一交付物。

## 5. 阶段二：组件、架构、流程与阅读体验

- [ ] 5.1 扩展组件输入、事件、暴露方法、内部状态和使用位置，贯通页面内嵌操作；验证助手→页面→组件方法转接及外部组件无源码边界。
- [ ] 5.2 增加应用边界、依赖、路由分发、共享状态/认证及请求基础设施关系；用 npm 组件集成反例验证不自动生成微前端主子应用。
- [ ] 5.3 对实际存在的跨应用通信提取双方、通道、载荷、触发和监听清理，形成有来源的架构图；验证缺少接收端源码时明确止于边界。
- [ ] 5.4 基于事实关系生成流程、规范和代码参考专题；验证流程包含失败/取消分支、配置声明不冒充强制执行、没有相应主题时不填空类别。
- [ ] 5.5 将专题关联、覆盖状态、问题和人工解释接入目录与 Markdown 预览，并更新 OKF 的发布事实版本和索引；验证当前发布/暂存隔离、链接可达、来源定位一致且不自动标 verified。

## 6. 阶段二：首次与关系驱动增量

- [ ] 6.1 扩展无变化比较覆盖政策、分析器/适配器、事实模式、范围和生成输入；验证代码未变但政策变化需要重建，执行游标变化不会单独触发重建。
- [ ] 6.2 按节点/文件变化与反向关系分析参数封装、权限和入口的影响；验证共享参数变更更新全部已确认调用方，闭包不可靠时明确扩大到模块或仓库。
- [ ] 6.3 实现新增、删除、移动与断边的事实失效及主题处理；验证可确认移动保留身份、歧义重命名不合并、删除路由修正索引且不静默删除人工内容。
- [ ] 6.4 对纯说明性注释变化区分行为无变化与证据行号刷新；验证不重写业务内容但新版本来源仍定位到正确实现。
- [ ] 6.5 将事实影响接入已有影响审批/章节补丁/CAS 发布，原子绑定正文、目录与事实版本；验证审批后基线变化、人工编辑和并发发布均被保护，纠错不会绕过审阅。
- [ ] 6.6 用双快照和跨组件/跨仓库样例验收新增、删除、权限、参数、版本差异、暂停恢复、预览和 OKF；提交阶段二源码对照与回归结果，明确所有未支持及未复核范围。

## 7. 阶段三：后端接口、调用链、数据落点与依赖

- [ ] 7.1 增加 Go 后端能力适配和路由/中间件/参数绑定事实，保留语言与框架能力声明；验证 HTTP 组路由及条件校验准确，无后端仓库时不运行该阶段或编造后端内容。
- [ ] 7.2 提取处理器→服务→仓储的可确认调用链，关联外部调用并记录分派候选；验证接口注入不确定、反射和依赖缺失不会拼成确定链路。
- [ ] 7.3 提取数据库操作及表映射、缓存键构造、消息目的地、事务与依赖；验证仅模型声明不算已写入，动态 SQL/环境选择无法定位时保留未知。
- [ ] 7.4 关联前后端方法/路径及前缀转换，输出字段、校验和响应使用差异；验证多候选、版本不同和前端多传字段不会被伪造为统一契约。
- [ ] 7.5 将后端专题接入同一来源、成文、增量、审阅和 OKF 流程；用可控 Go 样例核对接口到落点全链路及未知边界，真实后端项目尚未接入时单列实仓验收未完成。

## 8. 阶段三：人工纠错闭环与最终验收

- [ ] 8.1 扩展问题的待澄清/已补充/已复核工作流和版本历史；验证只有状态数值时不猜业务名称，人工解释保留独立来源，可查证部分升级须有当前实现证据。
- [ ] 8.2 提供按参数转换、权限、跨组件操作和后端落点的风险筛选及普通样本抽样；验证能查看样本分母、未复核部分、复核人/版本/结论，不将样本通过标为全库已验证。
- [ ] 8.3 让纠错生成候选事实版本并沿关系更新页面、API、后端专题与概览；验证错误字段来源被修正、发布保留旧版本、关联代码变化后复核标记待复查。
- [ ] 8.4 执行跨前后端的首次→发布→增量→人工解释→抽样纠错→再发布验收，覆盖租户隔离、暂停恢复、冲突及回滚入口；交付源码对照、模型输出、复核样本与限制清单。
- [ ] 8.5 按真实完成范围更新旧实施记录、部署/回滚说明及能力文档，完成相关自动化检查与浏览器 QA；验证没有把计划写成已实现，没有特定参考系统命名、没有自动数据清理或未经审阅发布。

## 9. 阶段四：领域知识只缝合不重造

- [ ] 9.1 增加来源项目库发布事实版本选择、领域/子域及大/细链路定义；验证只接受有权限的已发布项目来源，不解析旧正文冒充事实，不接受循环或领域到领域引用。
- [ ] 9.2 按 HTTP/RPC/JSF、MQ、调度与回调的已确认结构关系拼接节点；验证同名服务/topic 不足以连边，缺失端和未支持适配保留断点及补证需求。
- [ ] 9.3 生成领域核心链路、基础能力、全景/术语/缺口/索引，所有节点和边回链来源发布版本；验证异步分支、并行、重试、补偿和未知时序不会被压成虚假串行链。
- [ ] 9.4 来源版本变化触发关联链路待更新，审阅后发布新引用；验证旧版本不静默变化、补证交回项目库、只更新受影响链路。
- [ ] 9.5 将来源授权应用到领域阅读、导出与任务，增加源库撤权/删除处理；验证不能通过领域正文或 OKF 泄露已无权来源。
- [ ] 9.6 以多个项目事实样例完成首次领域拼接、缺口补证、来源升级和复核发布验收；交付来源追溯表和抽样纠错记录，不设置固定篇数或声称全局完整。
