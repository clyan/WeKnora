# Design

## Context

动机见 proposal.md。总原则：从代码建立知识基线，只写能从代码查证的事实；业务含义不确定时进入问题清单，人工补全并抽样核对。

已核对的现状：

- `code_wiki_frontend_planner.go` 提供分页文件清单、受控 list/search/read/topics/propose/finish 和规划检查点；清单逐文件处理说明不等于操作覆盖。
- `code_wiki_frontend.go` 有分类型写作要求，但正文取证最多选择部分锚点、每个锚点一个片段，不能保证追踪完整调用点。
- `code_wiki_generate.go` 的 `generateOnePage` 基本为取证后一次生成、引用校验、暂存；引用路径与区间合法不能证明事实正确或操作齐全。
- 当前已实现来源政策、注释过滤、语法候选存储及两种模式入口，但操作/参数完整追踪与正文按需补查尚未接通；这些基础不等于阶段一已经完成。
- `code_wiki_baseline.go` 已比较联合代码输入和生成配置；增量已有影响审批、章节补丁及人工保护，先接入主题依赖清单和保守扩大分析，不重写发布系统。
- 普通 Wiki 已有共享工作池、批次认领、单知识库并行批次上限、批次内 Map/Reduce 并发及同页更新锁。Wiki 与 Code Wiki 已共用 wiki 工作池，默认 8 槽；普通 Wiki 默认单库 4 个并行批次、Map/Reduce 各 10 路，不能把这些值视作模型调用总上限。Code Wiki 当前单任务内逐页串行，未自动继承普通 Wiki 批次内并发配置；Lite 模式也不能照搬 Redis 多 worker 假设。
- 现有前端具备目录树、Markdown 预览和执行事件。OKF 为已发布版本导出，内部仍使用数据库 Markdown。
- 主规格库当前为空；旧的 `plans/code-wiki/FRONTEND_OKF_IMPLEMENTATION.md` 为历史实施记录，其中“资料已有约定”等允许来源与本次决策冲突，以本次规格为新流程约束。实施时更新旧计划的定位，不能把它当成当前已完成承诺。

现有绑定的两个前端快照仅用于人工选取代表性案例，不写死仓库名、业务名、路由或文件数。当前知识库没有可供本计划依赖的后端源码，后端阶段使用可控 Go 样例验收；未来其他语言须增加能力适配，不能自动泛化。

## Goals / Non-Goals

**Goals:**

- 将证据资格、主题分析、专题成文、发布验证分层，复用检查点而非重复全仓分析，单独记录失败与未知范围。
- 先交付前端页面/API 的完整可检查链路，已有 UI 和存储能力继续复用。
- 首次分析建立基线；以后按主题依赖及证据变化更新，代码、人工解释和抽样复核保持版本对应。
- 按主题受控并发，跨轮上下文有预算，前端能同时观察所有活动主题及排队/暂停原因。

**Non-Goals:**

- 静态分析穷尽所有动态行为、证明线上实际执行或赋予模型语义证明能力。
- 用前端猜测后端、把人工业务解释无条件升级为代码事实，或把抽样通过扩大为全库验证。
- 本计划阶段删除数据库、执行仓库脚本、重新发布知识或调用生成模型。
- 建设独立通用事实数据库、复制完整代码图/语法树、业务本体与决策执行平台；不把这些作为深入源码分析的前提。

## Decisions

### 1. 将来源政策放在工具与校验层

新增版本化来源资格分类。授权清单仍完整保存，但对模型的业务取证视图只提供合格的实现片段及相关配置；README、Markdown、说明性注释、Mock、样例和测试内容不进入事实取证上下文。测试可验证分析器，不用于证明被分析项目行为。

文件角色结合路径模式、内容特征及引用上下文判定，不以目录名决定业务主题。识别为 Mock 的内容即使位于普通 src 路径也不能作为真实业务证据；不能可靠识别的源角色记为待确认，不擅自通过。生产实现引用 Mock 时只证明引用到模拟源这一事实，不把模拟结果写成真实契约。

JS/TS 分析通过语法节点提取实现，过滤说明性注释并保留原行号映射。遇到编译指令，仅记录其对解析/构建的已确认作用，不能利用说明文字补业务语义。原源码点击查看仍可保留注释，但传入模型的证据应使用过滤视图。搜索命中和图候选需回读合格节点后方可接收。所有读工具、正文生成与补丁走同一政策，不能从旧笔记、旧索引摘要或旧正文绕过。

选择此方案而非仅修改提示词，是因为模型一旦读到过时解释就可能被锚定；但文件角色识别和语义仍有误差，资格校验不等于已证明业务准确。

### 2. 主题检查点承担记忆，代码索引继续管理结构

每个知识主题保存一份版本化分析记录，优先扩展现有任务/候选存储；并发调度或事件需要独立记录时增加最小迁移，但不建设通用事实/关系账本，不将整个任务的所有主题塞回共享配置 JSON。现有语法候选表兼容读取，不自动删除、不作为已核验结论或新执行前置依赖。

| 内容 | 关键内容 |
| --- | --- |
| 主题身份 | 租户/知识库/任务、主题键、仓库与快照集合、分析配置版本、检查点修订号 |
| 已查明结论 | 主题内局部键、结论、条件、声明/实现/未知状态及证据引用 |
| 证据清单 | commit、path、源区间、内容指纹、来源资格；源码原文保留在快照 |
| 已发现项与待查问题 | 操作、调用点、字段及直接依赖，已完成/待查/未知原因，后续定位线索 |
| 成文与复核 | section→主题局部项映射、覆盖结果、人工解释/样本记录、发布关联修订号 |
| 调度状态 | 租约/写入代次、执行步骤、尝试次数、预算占用、最后活动、输出版本 |

参数仍按调用点保留字段来源、默认值、转换与分支，不合并为统一后端 schema。codebase-memory/自定义 Provider 管理索引和结构候选；平台解析器提供过滤及局部结构，模型结论必须回读合格源码，不把图查询当作证明。

主题跨轮复用已查结论、待查事项和证据，不复用完整对话或只有摘要的猜测。跨主题首次允许重复查询，读取/解析缓存按租户授权、知识库、仓库快照、内容指纹及政策/分析器版本隔离；不依赖所有主题共享可写事实图。公共逻辑结论不一致时登记冲突并补查，禁止最后完成者覆盖其他主题结论。

选择轻量检查点而非独立事实账本，降低同步、建模和部署成本；代价是跨主题可能重复分析，增量粒度先到主题，不能宣称逐条事实精确闭包。

### 3. 解析器负责候选结构，模型负责有界解释

首批采用固定版本 TypeScript 编译器 API 提取 JS/TS/JSX/TSX 的 import/export、JSX、调用、对象构造和控制条件，并封装为受控分析进程；复用平台现有代码索引提供跳转与候选。实现不得执行被分析仓库代码、安装仓库依赖、加载其插件或运行配置文件。部署需提供固定分析运行时和健康检查，缺失时显式报未支持，禁止回退猜测。

从注册与使用关系发现路由、页面及组件；框架/请求封装通过能力适配解析，未知封装可由模型提出补读问题，但只接受带可核对实现节点的关系。静态解析可处理局部赋值、对象展开、默认参数、条件构造和可解析辅助函数。动态键、复杂别名、反射和不可访问依赖保留 unknown。

模型不能直接提交“覆盖完成”的自由文本。按主题提交结论、证据清单、已发现项及待追踪问题，系统验证来源和对应关系；人工抽样检查语义。解析器只提供候选，不要求全仓全部节点先落库才能分析。

### 4. 从操作与调用点驱动多轮分析

目录发现采用索引候选批量规划：程序从冻结快照对应的 codebase-memory 索引分页查询声明及 IMPORTS/CALLS/USAGE/HTTP_CALLS/HANDLES 位置关系，按授权文件整理有界导航摘要，由模型按批次归并、命名并分配类别；不再要求模型逐文件 read/search 后才能提出专题。架构概览仅为有界参考，不冒充完整清单。文档、Mock、测试及不支持来源不进入业务候选上下文；没有索引声明的合格文件仍保留为待查候选。候选及其源码锚点不是已读证据或已接受事实，具体操作、权限和参数继续由主题分析核查。缺少结构查询能力明确报错，不静默回退逐文件模型循环。旧逐文件规划检查点不直接恢复到新策略。

目录规划先由程序聚合结构模块：按目录局部性保留完整文件清单，索引明确的路由/处理入口独立保留；仅在真实依赖存在且为单一使用方时，将有界子目录并入调用模块，共享依赖保持独立。所有已取回的关系参与聚合，不只使用提示词中的关系样本；目录不是业务类别依据。模块是可拆分的导航桶，不是强制一篇文档。向模型只发送一次目录前缀、文件相对路径与短标识、少量符号及去重模块依赖，不回放逐符号重复的全路径、行号和调用边；完整位置仍供主题查找，符号样本与依赖省略计数明确。

现有串行实现的候选批次默认最多 256 个文件、约 48KB 模块导航，并根据模型容量估算继续缩小；模块有独立大小限制，单模块装不下时保存暂停。这是已交付的基础保护，不等于下述并发聚簇与分层兜底已经实现。模型可用模块或文件短标识归类，逐文件原子覆盖校验继续有效，每项须进入一个或多个专题或保留具体未分配原因，没有固定文章数。`indexed-candidates-v1` 检查点经原候选指纹、游标与逐路径记录验证后迁移到现有模块策略，保留已有专题；更早逐文件阅读策略仍拒绝静默迁移。

#### 4.1 入口聚簇与预算分批并发规划（待实现）

拆分采用“模型提议、工具校验、程序调度”：先向模型提供 codebase 的有界入口/符号/依赖导航与规模摘要，允许按需查询局部结构后提出簇边界、共享引用及拆分依据，不要求模型阅读全部源码。小范围可一次提议，大范围必须分页或局部查询；一次调用是优化目标，不是牺牲覆盖或预算的硬约束。程序校验授权路径、逐文件交代、依赖依据和容量，只有边界无法由结构确定时才按具体问题局部回读。增量默认复用已发布划分，只对变更和关联范围提出调整，批次身份不得替代内容身份。

新策略按“冻结结构清单 → 模块簇 → 预算批次并发提出候选 → 统一核对 → 确定初步目录 → 主题分析”执行。簇是结构关联范围，不是单次请求或最终文档。入口以可定位的路由、挂载或处理注册线索为种子，沿已取回的授权依赖关系形成局部簇，不能只靠目录名、名称相似度或递归可达性划分。多个入口共同使用的模块保留独立身份及入边，业务簇引用其有界接口/位置摘要，不将公共节点作为连通桥把全仓合成一簇；循环关系先作为结构边界处理，不无限展开。无明确入口、索引未命中及动态关系不确定的合格文件保留独立待查候选及原因，不能从全量交代清单消失。

簇、分片和批次具有版本化身份及内容指纹，绑定租户/知识库/运行/快照、政策、规划策略、分片范围和跨批边；内容身份不取决于 worker 完成顺序。先按局部子入口、依赖局部性和公共依赖边界形成分片，避免只按路径和容量装箱。每个待处理文件或结构导航页都有归属记录；共享引用与实际分配范围分开计数，一个文件支持多个专题不算错误重复。完整清单、边界和分页游标保存在系统，不要求把全部源码或图装进一次请求。无法可靠分开的单个大模块使用分页路径/符号导航，细节在主题分析分段回读；若连最小合法单元也装不下则明确暂停，不靠丢弃路径解围。

预算检查分两级：本地缓存同版本导航项的估算大小，装箱时粗估；每次发送前对实际系统指令、当前批次、相关主题身份、工具结果和修正反馈检查所选模型上下文预算，预留输出与安全余量，工具步骤另留返回空间。缓存仅减少重复计算，不代替最终检查；未知容量沿用保守配置。256 文件/48KB 仅是默认导航装箱上限，不是 token 容量保证。汇总、修复及重试请求同样检查预算，禁止为了缩小输入静默移除未处理项。

每个规划批次独立认领、保存候选、逐文件交代和检查点，写入核对执行代次及修订，不能多个 worker 同改 run 配置 JSON。复用共享 Wiki 工作池、租约生命周期、模型并发和任务调用预算；规划并发单独冻结生效值，默认 3、范围 1–8，仍受共享模型上限约束，不增加重复设置入口或 RPM/TPM 配置。父调度器派发后释放执行机会，不占满工作池等子任务。已通过批次保留且不重复调用模型；失效执行者、重复消息和跨快照结果拒收，暂停/取消停止派发并拒收迟到输出。

超限兜底顺序固定为：减少本批模块数 → 按子入口/局部依赖拆大簇 → 单模块分页结构导航 → 仍不可容纳则保存暂停。提供方实际返回上下文超限时保留已成功结果，降低该批有效输入预算并重新分片；每个原批次自动修复最多 2 次，各子片继承原批累计次数和总调用预算，不能靠递归生成子批重置重试次数。自动重试前必须有更小的实际请求，原样请求不能重复发送；无法再缩小或次数耗尽时只暂停该批及依赖它的核对范围，其他独立批次可继续。任务总用量耗尽或用户主动暂停属于全局控制，仍停止全任务派发。上下文错误与限流退避分开处理，未解决批次存在时整体规划不能标完成或进入主题正文执行。

候选就绪后先由程序校验范围归属、合法身份、重复来源和遗漏，再按入口/来源重叠/跨批关系检索需要比对的候选，分批核对身份及专题范围；不得一次回放全量候选或做全量两两模型比较。核对输入以主题键、范围、结构边和待解决问题为主，源码只在冲突需要时定向补读。相同标题不构成合并理由，多个专题合理引用同一文件也不能被强行合并；不确定合并保留双方和待查关系。分层核对必须保留全部候选的去向及跨分片边检查记录，局部预算不足继续拆分或暂停，不能因为摘要装得下就跳过未核对候选。

最终接受初步目录时核对规划版本与全部批次修订，以事务或等价原子发布方式登记稳定主题键、来源范围、别名/合并映射和跨批关系；失败不部分覆盖已有目录。目录核对只是候选一致性检查，不是业务事实验证或全仓完整性证明。增量复用已发布主题身份，按变更和已知依赖仅重规划受影响范围；分批、聚簇顺序或 worker 完成顺序变化不改未变主题。依赖缺口需要扩大范围时显式说明并进入既有影响审批，不借全局重新聚簇隐式改标题、目录和正文。关系驱动增量未交付前保留明确的全范围重分析提示，不能提前宣称该身份稳定性目标已实现。

进度按批次保存仓库、快照、簇/分片及完整路径的可分页引用、阶段和修订，展示聚簇、排队、规划、缩批重试、暂停与统一核对等实际状态；支持多个活动批次而不是共享单个 planning_batch。兼容旧任务最近一批视图，刷新和乱序响应不覆盖用户选择。新执行协议显式版本化，已有已接受批次只能经输入/范围指纹验证迁移，不自动重启旧任务或把串行游标直接当并发完成集。

以下逐文件读取账本及导航保护保留给历史规划实现和主题源码阅读；新任务目录规划不再执行该逐文件模型动作协议。

执行次序：冻结输入与政策 → 轻量发现入口和使用关系/初步主题 → 主题持续取证 → 专题成文与补查 → 概览/索引 → 审阅发布。主题可随分析增补、合并和拆分；发现阶段已有合格阅读结果带入主题，不安排规划与正文各全仓扫描一次。

单主题执行“选择未完成问题→定位/读取→登记结论、证据与新问题→保存检查点→继续”。同一条有依赖的追踪链有序推进，独立主题并发；首批不增加主题内部无限分叉并行。记录 discovered/analyzing/analyzed/unresolved/unsupported/excluded 等分析项状态，与 queued/running/waiting/paused/failed 等调度状态分开。证据丢失、工具失败或预算耗尽不是分析完成；动态边界可登记原因后进入带缺口的成文。

受控工具保留分页、限定行数、租户/快照约束及额度，新增读取主题检查点和待查事项。每步幂等保存后再推进，重复查询及循环依赖有已访问记录；预算耗尽暂停，进程重启恢复同一版本。摘要仅作导航，不设置总文章数上限。

目录规划同样带入成功读取记录的有界分页窗口，完整记录保留在原规划检查点，不建设额外事实库。源码返回明确实际行段、文件总行数、截断及文件末尾；按完整行裁剪，只将实际返回行段登记为证据，保留空行与缩进以维持原始行号。完全被既有范围覆盖的读取可用于恢复上下文，但不视为新证据。连续两步没有新增源码覆盖、主题或清单进展时提供纠偏及未读候选；连续八步仍无进展时保存并暂停，不强制跳过文件或生成目录。导航与修改笔记不重置该计数；用户继续时获得新一轮有界纠偏机会。真正增加阅读范围的长文件分段不受该无进展阈值限制，仍受原调用预算约束。

规划清单不再仅按字母顺序递交模型：依赖/导出声明、入口与路由候选、普通实现优先于类型声明和工具配置；路径仅决定导航顺序，不证明页面/API 或业务含义，不排除非标准目录。提示模型从实际导出/注册向调用方、操作和参数来源追踪，取得合理锚点即保存初步主题，详细条件交由主题继续取证。完整文件清单与原指纹保留，重排后按逐路径 Decisions 选择尚未交代的批次，Cursor 只表示已交代数量；旧检查点也不能把新顺序的前缀误认作已处理。

静态图像/字体/媒体/样式及来源政策已排除文件，保存逐路径原因并计入清单处理，不能宣称读懂实现。生成的 SVG 图标脚本须由实际赋值语法、占主要内容的 SVG 字形载荷及保守的纯资源条件识别，名称、注释或 public/lib 路径不能单独决定排除；混有导出、JSX、其他全局赋值或请求调用的脚本保留。其引用/交互仍从使用方取证。未知脚本不自动视为静态资源。

重复已读范围默认仅返回导航提醒；确需恢复源码须附具体待核对问题，仍受调用预算和累计重复读取保护。新增文件读取只重置连续无进展计数，不重置累计重复读取；只有新增真实主题或交代当前批次才重置累计值。累计八次重读同样保存暂停，避免“新配置→旧配置→新配置”绕过保护；用户继续获得新一轮有界机会，不限制合理新增证据或文档篇数。

前端阶段尚未实现关系驱动增量前，新任务应明确执行范围内重新分析再与已发布版本对比，不能伪称精确增量；仍保留人工修改保护。

### 5. 先生成专题，最后生成概览

页面、API、组件、架构、flow、规范、代码参考和待澄清问题分别提供平台内置 Markdown 写作模板，由同一个 frontendPageInstructions 入口注入主题成文协议。模板是内容结构要求，不等于语义校验通过；API 按调用点列真实字段来源/条件/转换/覆盖顺序，flow 按步骤列输入输出、调用连接、分支、失败和取消。主题初始待查问题随类别选择，不能让 API、规范等所有类别套用页面按钮问题。用户的内容偏好继续附加，不能放宽来源政策；本次不新增模板编辑界面。

正文输入由主题检查点中的结论、条件、证据及未知构成，返回 Markdown 和 section→主题局部项映射；系统检查每个已发现操作/调用点是否在正文或问题中对应。正文遇到证据缺口返回同一主题分析器，沿用已有结果补查，不重新独立检索固定数量片段。引用检查与已发现项覆盖检查分别报告，都不保证发现全部行为或证明每句话正确。

各类专题统一在文末展示“源码依据”，不在正文插入证据编号或表格证据列。系统根据 section→分析项→evidence_ids 校验已查明结论，并按证据清单顺序去重生成文末的仓库、源码行段及提交版本；不把全部读过但未用于结论的片段列入依据。兼容旧检查点时先校验已有引用再移除正文编号，未知引用仍报错；取消内联引用不取消逐项证据与覆盖校验。

页面表包含触发、显示/禁用、校验、动作、API/参数来源、状态/跳转、失败与加载行为。API 按真实调用点描述字段，区分类型声明、实际传入和请求封装追加；没有调用点写明查找范围。组件记录输入输出、暴露方法和实际使用。通信记录双方与载荷，不存在时不造主子应用。

规范只收集实现中的工具/配置约束与观察到的写法，不能把重复写法说成强制要求。references 仅容纳代码定位、声明差异等有用参考；不再从旧文档生成业务参考专题，也不填充空类别。

主题分析就绪即可成文，不等待所有主题；概览在本次发现结束且相关主题终结后汇总，失败、暂停及缺口明确展示，不拿未就绪任务当作结果。链接只用已存在页面身份。架构图的边来自主题依赖清单中的已确认关系，不以示意图补充没有的事实。

### 6. 首次、增量和规则升级共用版本模型

当前已接入保守主题增量基础：兼容已发布配置才能复用目录，执行并发、预算、游标及全量/增量标记不单独触发重建。索引规划保存每主题的完整已取回传递依赖路径；后续跳过已有源码的重复命名，只为新增文件提出或扩展主题，已有标题、路径和顺序沿用。影响判断合并旧依赖、新依赖和已发布主题实际取证路径；唯一且内容完全相同的同仓删除/新增对可更新源码位置而保留主题键，歧义不自动合并。无依赖基线、未知分析项、新增源码、配置或跨仓库关系缺口保守扩大复核范围，不宣称完整静态闭包。

本基础版本以整个受影响主题为审批和重新取证单位，复用旧审批面板并显示明确的整主题更新项，不冒充字节级章节补丁。必须确认全部受影响主题后才能推进联合代码基线，避免未更新主题的变化在下一轮被遗漏；执行途中不能自行拆合已冻结主题。未受影响主题复制结构化分析供概览使用，源码行段在确认文件未变后对应当前快照，已发布正文及其历史来源不写入、不换版本、不更新时间。发布事务核验整页原始指纹、审批范围和人工编辑，全部成功后才推进发布基线；失败/暂停不推进。

删除生命周期由程序驱动：双快照 diff 确认全部所属源码删除、同仓范围未变且没有新增替代歧义时，冻结归档主题指纹并提供单独的 archive 审批项，不调用模型生成失效主题。部分删除只剔除失效分析锚点，联合旧依赖重新取证；唯一同内容移动已先更新锚点，不误归档。新增/删除并存或过滤变化不推断主题消失，仍要求重新核对。归档是用户发布时的事务操作，保留旧正文、历史修订和旧版本证据，退出当前目录与检索；新归档版本不复制已删除源码证据。后续规划跳过归档主题，已保留的主题身份不能被新增提议隐式恢复。

其他文档的入链纳入审批；源码未受影响且仅需清理链接时，程序只把归档目标的 Wiki 链接转成可读文本，其他字节及分析结论复用，仍保留新旧版本记录。概览汇总跳过待归档结论，全部主题归档时用基于删除清单的空阅读导引，不伪造源码事实或调用模型。发布事务检查最终正文与缓存入链，任何当前页面（包括人工维护页）的残留链接均阻止整轮提交，不擅自改写范围外文档。主题归档与关联清理、概览更新一起提交，原始指纹、人工维护保护及零越界写审计继续生效。

剩余阶段二验收继续保留：基于框架语义确认入口消失、动态边界和歧义移动/替代、纯注释的定位刷新、精细跨仓关系与章节级最小补丁、完整双快照真实模型验收。上述基础及合成回归不代表 6.1–6.7 已全部完成；并发规划 3.16–3.21 也仍独立待实现。

运行冻结来源政策、分析记录模式、解析器、框架适配、生成设置及模型版本。无变化比较涵盖这些输入；执行游标、租约和事件序号不参与内容差异判断。

首次全范围发现并保存未支持/排除清单。后续依据文件变化和主题证据/依赖清单选择主题重新分析，不承诺独立事实图的逐条精确增量。公共请求、权限和入口变化扩大到已知调用主题，依赖不全或动态边界无法判定时扩大到模块/仓库并说明原因。新增/删除和断边参与影响审批；纯注释变化区分行为变化与定位刷新，不能保留过期引用。

旧发布内容维持可读，标注旧政策；新任务建立主题分析基线，不从旧正文导入结论。旧活动任务只读/停止后新建，不混换检查点版本。发布沿用审批、章节补丁、人工编辑保护和 CAS，原子关联正文、目录、来源清单及主题修订版本。

### 7. 后端作为独立阶段复用主题分析机制

有真实后端源码后新增 Go 适配器，使用语法与类型信息追踪 HTTP 注册、中间件、处理器到服务/仓储的可确认直接调用。允许对现有索引候选做端点核对，不把图完整性当作保证；类型检查依赖不可用时明确降级为候选。

数据落点要同时关联调用和映射：数据库操作及表映射、缓存键构造、消息目的地、外部服务地址构造和事务边界。只有模型定义或函数名不算落点。接口分派、动态 SQL、运行配置选择无法确认时终止确定链路并记录未知。

前后端以方法/路径及有证据的前缀转换匹配，记录字段、校验和响应差异；多候选或版本不一致进入问题，不产出看似统一的契约。缺少后端源码时后端阶段不运行，不阻塞前端知识交付。

### 8. 人工澄清与抽样核对不混入事实层

问题记录技术上已知的条件与未知业务含义。用户可填写人工解释，保存人员、时间和版本，阅读/OKF 标明来源；不能仅因人工点击确认就成为代码事实。若新增代码证据，复核后将可证实部分关联为事实，其余解释继续保留独立属性。

基础问题、解释及样本记录随第一阶段交付；第三阶段补全风险筛选、批量核对和跨前后端纠错传播。抽样优先覆盖参数转换、权限条件、跨组件操作和后端落点；同时保留普通样本，避免只检查简单项。记录样本分母与未核对范围，不硬编码通过率为全库质量证明。

纠错生成新的主题分析修订和候选正文，更新相关页面/API/概览后复核发布，不直接覆盖已发布正文。证据或条件变化使关联复核标记待复查。

### 10. 项目代码与领域两种模式

新增明确模式 project/domain；历史配置缺省 project。创建时选定，已有事实或任务后不得原地切换混合来源。项目库可包含同一项目的多个前端、后端和共享包仓库；领域库绑定已授权的项目库发布版本，而非 Git 仓库。领域执行入口未交付前明确提示能力未开放，不能把它送进项目代码规划器。

项目库发布时提供结构化跨项目依赖清单；引用包含 source_kb_id、published_run_id、topic_key、analysis_revision、entry_key 及源码证据，不要求通用 fact_id/关系数据库。领域不解析 Markdown 冒充事实。一级域关联大链路，二级域关联细链路；领域命名和边界由用户确认，不以示例篇数为目标。

连接是有类型和条件的边：HTTP/RPC/JSF 核对服务/方法和配置；MQ 核对生产消费目标、环境、过滤和载荷；调度核对注册、触发和后续动作。只找到同名 topic 或相似接口不能认定因果；异步流程保留分支、并行、重试、补偿和未知顺序。语言/中间件适配未支持时记断点，不从术语推测实现。

领域只缝合，不重造：缺证交回项目库补取证并发布，领域再选择新版本。底层更新标记关联节点/边待复核，经审阅切换引用；不原地改变旧发布版本。来源撤权或删除时停止新生成并隐藏无权内容，不能通过领域正文或导出绕过来源权限。来源版本组成图必须无循环，领域到领域引用首批不开放。

### 11. 上下文预算由执行器负责

每轮新建消息集合，仅包含强制政策、当前主题/问题、相关已查结论和待查事项、必要源码及最近动作结果。不追加全部工具历史，也不把前面读过的源码全部转交正文。长结论记录按局部项分页查取，摘要不能替代证据。

用模型配置的上下文容量和 tokenizer（可用时）估算输入，分别预留输出、工具返回和安全余量；未知容量使用明确的保守配置并展示限制。单纯字符数不能作为适配所有模型的保证；提供方仍拒绝时拆分输入或暂停，不无条件重试相同超限请求。

大函数按结构和行段读取，保留函数、词法作用域、条件和来源标识。证据大于单轮预算时拆问题或分页，不以截断成功作为分析完成。输入达到阈值先提交检查点，再按问题开启下一轮；每次调用计入任务预算，失败调用也不绕过上限。

### 12. 复用 Wiki 并发机制，主题为独立调度单位

抽取认领后的租约生命周期、续租/停止、并发占用和所有者锁释放通用机制，两类任务保留各自语义与配置。普通 Wiki 继续按文档去重键认领批次，Code Wiki 继续按主题修订及有效执行代次认领；存储原子操作留在各自仓储，公共层不新建通用任务账本。Redis 对象锁复用现有所有者令牌原语，并发槽续租不得重建已经失效或释放的占用，停止须等待续租退出后再释放。Lite 的进程内互斥与主题持久认领分别匹配实际运行方式。继续共用 wiki 工作池，不复制第二个无协调调度器，也不将 Code Wiki 硬塞入普通 Wiki 的文档 Map/Reduce 流程。Code Wiki 新任务默认单库三个主题并发，可配置并冻结本轮配置；普通 Wiki 的 Map/Reduce 值不自动变成主题并发值。

一个主题一个可认领单元；入口负责发现和汇总，不长期占用所有工作槽等待子任务，避免父子任务互相等待。主题注册按稳定键去重，目录调整保留别名/合并记录和证据归属；同一主题的依赖链首批串行，多主题可以同时分析或成文。全局状态、计数和检查点不得通过多个 worker 改写同一 run JSON；主题结果独立提交，汇总计数以数据库状态为准，非原子共享 CompletedPages++ 不再作为并发依据。

每个主题携带租约代次及检查点修订号；写入须同时检查租户/知识库/运行/快照与有效代次。租约过期可重领，旧 worker 的晚到结果拒收。认领和终结幂等，失败主题不回滚其他主题成功成果。共享缓存仅复用过滤后的相同版本源码/解析，不执行项目脚本。

三个额度分别控制：共享后台槽位、单库所有活动任务合计的主题占用、模型请求并发及任务调用预算。复用现有模型并发机制并核对其覆盖范围，不以 UI 参数或单进程信号量代替多 worker 限额。任务调用总预算在派发前原子预占、结束后结算/回收，重试也受限；等待模型调用不占用活动请求槽，退避重排防止一个库饿死其他任务。按用户决定，不新增全局 RPM/TPM 限速、每分钟额度配置或相应前端入口；提供方返回限流时仍按现有策略退避重试，上下文容量保护及用量记录保留。

暂停/取消停止新派发，并对执行中的工具/模型协作中断；不可立即中断的请求显示收尾状态，迟到输出通过代次检查拒收。排队和等待不显示运行中的 loading。单主题失败可重试，成功主题保留；总任务状态依据子任务聚合，发现未结束、仍有排队/执行/暂停项时不能标完成，终态必须区分成功、带缺口、部分失败和取消。Lite 模式复用进程内有界调度和持久检查点，不能假装跨进程锁生效。

### 13. 前端从单步骤切换为多主题进度

目录发现/规划使用独立 90 秒租约、每 15 秒续租，模型等待时间不影响存活信号；每次认领生成唯一执行令牌。启动及每 15 秒扫描失联任务，按观察到的状态、所有者、租约时间和更新时间条件更新，避免与续租竞争；确认失联后仅转为“执行已中断，进度已保存，点击继续生成”，取消请求优先进入取消状态，不自动调用模型。正常关闭只暂停当前进程令牌前缀匹配的任务。历史长租约按原 TTL 还原最后续租时间，避免等待数小时才恢复；已转交主题执行的任务仍由主题租约及持久调度恢复。规划写入携带内存中的认领令牌，检查当前所有者、有效期和工作状态，拒绝失效执行者更新检查点、终态或复活被删除任务。恢复保留冻结快照、已接受文件归类、主题、候选与用量；未完成的当前批次由用户继续后重做。

目录规划在模型调用前将本批仓库/快照、模块和完整相对文件路径保存到规划检查点，通过任务详情的 planning_batch 返回公开范围，不需要增加数据库表。仅提供与本轮授权清单一致的仓库/快照，不返回源码或提示词。前端在当前动作下提供原生 details 折叠区域，默认关闭，按模块列路径并说明索引候选不代表源码分析完成。批次以来源文件和快照生成稳定身份，轮询不重置用户展开状态，换批次/任务恢复默认关闭；刷新从持久进度恢复范围，成功归类后保留最近一批，旧任务缺字段不显示。

易于理解是整个 Code Wiki 界面的要求，覆盖创建、设置、生成、阅读、审阅、发布及错误反馈。默认使用用户任务语言而非内部实现术语；状态回答“现在做什么”，等待/异常补充“为什么、是否自动继续、需要做什么”。正文、按钮、空状态和提示使用一致称呼；技术详情、错误码及诊断标识按需展开且脱敏。信息先给结论和必要操作，再给细节，不要求用户从日志判断任务是否卡住，也不编造原因或恢复时间。

统一状态文案例：等待后台执行机会显示“排队中”，模型请求槽暂未空闲显示“等待模型调用”，提供方限流显示“请求过于频繁，稍后自动重试”；本轮预算耗尽显示“本次生成已达到设置的用量上限，进度已保存”，仅在确实支持继续时提供对应操作。自动恢复的等待与需要用户处理的暂停必须区分，不统称“等待额度”。执行动作优先显示“正在阅读订单页面”“正在核对提交参数”，文件路径和行号在详情中辅助定位；这些动作必须来自实际事件。

沿用现有任务面板和审阅入口，不再新增生成设置入口。总体卡片展示发现阶段、当前并发占用/上限、主题总数（发现中可增长）、排队/分析/成文/等待/暂停/成功/失败数量及额度等待原因。分开统计文件清单、已发现项分析和文档产出；分母未稳定前不显示虚假的固定总进度或 ETA，重试不重复累计成功项，数量都不是全仓语义完整率。

主题列表默认突出活动和需处理项，可筛选状态，活动项稳定排序，展开显示当前问题、实际动作、文件行段、尝试次数、最近活动、未知边界及分页事件；允许边生成边预览已就绪候选。用户主动选择的主题/文档不因其他主题事件或自动排序被切走。暂停/继续/取消任务及重试失败主题依照写权限，单主题控制首批提供失败重试，不默认新增所有主题独立暂停功能。

事件包含 run_id、topic_id、attempt_id、step_id、事件 ID/序号、状态、时间和脱敏位置，事件与可恢复步骤关联；并行事件只展示实际记录顺序，不暗示因果。以持久快照+分页游标轮询扩展当前 API，无需将 SSE/WebSocket 作为前置。首次加载及刷新先读取汇总和主题快照，再增量取事件；事件去重、旧响应防回退，断点失效时返回重建快照指引。保留既有单步骤历史任务只读展示，新版字段版本化，不能因缺少主题数据误显示新任务已完成。

执行中仅对应活动步骤显示 loading；等待、暂停、失败、完成分别有状态标识，完成/取消/租约失效时清除活动标记。多 worker 事件不相互覆盖全局 phase；页面隐藏/关闭停止轮询，重新打开从服务端恢复，长事件列表分页而非持续堆积。事件保留动作摘要而非隐藏推理、完整提示词、源码全文或凭据；多租户授权覆盖汇总、列表、详情、重试和事件接口。

## Risks / Trade-offs

- [语义错误仍可能带合法源码引用] → 结构检查只防来源和漏项；保留人工抽样、纠错和不可证明边界，不使用自动 verified 标识。
- [解析与模型重复工作、调用成本增加] → 解析候选缓存按内容/版本复用，多轮只解决未完成边；预算暂停可见，不能省略分析以换取“已完成”。
- [过于依赖文件名排除导致漏掉实现或引入 Mock] → 来源角色有内容和引用核对，歧义明确记问题，完整授权清单独立保存；主题分类不靠目录。
- [排除注释失去业务名称解释] → 使用实现可查证的描述，不确定术语留待澄清，不用读起来顺畅替代真实依据。
- [增量关系遗漏影响范围] → 关系不完整或未知分派时扩大扫描并标明原因，不声称精确闭包。
- [检查点太大或退化成未校验摘要] → 按主题分片保存、按问题取回，结论必须有源码证据；不复制完整图谱或对话，存储兼容按版本发布。
- [并发叠加导致限流、重复写入或进度失真] → 统一额度、原子认领和预算预占、写入代次校验；限流等待明确展示，计数以持久状态聚合，父任务不占满共享工作池。
- [模型容量未知或 token 估算失准] → 明确保守配置、工具/输出余量、拒绝后拆分/暂停；不得承诺不可能超限。
- [第三阶段后端语言覆盖有限] → 首批 Go 范围公开，其余源码清楚标未支持；后续适配不改变来源与复核契约。

## Migration Plan

1. 先梳理现有任务/候选/事件及已建事实记录，优先复用，必要时最小新增主题调度与检查点字段/表；PostgreSQL/SQLite 兼容迁移，保留现有数据，不强制新建通用事实账本。
2. 提供固定分析运行时和能力健康检查，新任务切换新版本；旧活动任务停止后另建，不能混用检查点。
3. 更新默认提示词、用户设置说明与强制政策提示；自定义内容保留，违反政策部分不执行。
4. 先单主题闭环，再启用有界主题并发和新版进度，验收限流/重试/重启/乱序事件/取消收尾；并发可配置为 1 降级但不得回退旧片段成文。切换初期全范围重建及正文对比，延续人工保护，不自动发布或清理历史。
5. 回滚时停止新分析派发并禁用新生成入口，保留已发布内容、检查点版本及新增字段/表；旧模式不得重新生成冒充新政策。破坏性删表不作为运行回滚步骤。
6. 本变更完成后再更新旧实施计划与主规格，未完成任务不提前归档为已实现。
