# Code Wiki 使用指南

Code Wiki 是一种知识库类型（`code_wiki`）：**一个知识库关联一组相关的 GitLab 仓库**（前端、后端、公共服务、公共库等），仓库是分析输入，基于这些仓库联合生成的 Wiki 文档是主要产物。文档中的每条关键描述都绑定代码证据（仓库、commit、文件、行号），可一键跳回 GitLab。

实现细节见 [CODE_WIKI_IMPLEMENTATION_PLAN.md](./CODE_WIKI_IMPLEMENTATION_PLAN.md)。

## 1. 前置条件

| 条件 | 说明 |
| --- | --- |
| GitLab 访问凭据 | 一个 GitLab access token（至少需要 `read_api` + `read_repository` 权限，能访问目标仓库）。创建数据源时填入，加密存储 |
| 大模型服务 | 生成 Wiki 页面需要已配置的模型服务；不强制配置 Embedding |
| 分析引擎 | 默认使用内置引擎（codebase-memory-mcp CLI）。使用 `docker/Dockerfile.app-codebase` 构建的镜像自带该 CLI，无需额外配置；也可切换为自定义 MCP 服务（见 §3.1） |
| 权限 | 知识库管理员才能配置数据源、仓库和发起同步/生成/发布；查看者可阅读 Wiki 与证据 |

## 2. 快速开始

整体流程：**创建知识库 → 配置 GitLab 连接 → 添加仓库 → 同步 → 生成 → 发布 → 阅读**。

### 2.1 创建知识库

知识库列表 → 新建 → 类型选择 **「代码 Wiki」**。可选填写生成限额（语言、每次生成最大页面数、最大模型调用数、超时分钟数），留空使用默认值。

### 2.2 配置 GitLab 连接

进入知识库 → 设置 → 数据源 → 新建 GitLab 数据源。**Code Wiki 模式下数据源只承担连接职责**（GitLab 地址 + token），创建向导第二步会提示：仓库与分支请在「代码仓库」标签页中添加和维护。

需要接入多个 GitLab 实例或不同凭据时，创建多个数据源即可，每个仓库可独立选择所属数据源。

### 2.3 添加仓库

知识库详情 → **「代码仓库」** 标签页 → 「添加仓库」：

- **数据源**：选择哪个 GitLab 连接
- **项目**：GitLab project ID（数字）或 `group/project` 命名空间路径
- **角色**（可选）：frontend / backend / service / library / other，用于联合分析时区分系统组成
- **分支**（可选）：留空跟踪默认分支
- **包含目录**（可选）：只分析这些目录
- **排除规则**（可选）：glob 模式，排除生成物、测试数据等

`node_modules`、`.git`、`dist` 等构建依赖与产物、图片字体等二进制、`.env`/密钥类敏感文件在快照层默认排除，无需重复配置。

### 2.4 同步

点「同步」（单个仓库）或「全部同步」。同步是异步任务：下载该仓库固定 commit 的源码归档、按过滤规则解包为不可变快照、并准备分析索引。

- 仓库状态流转：`idle`（未同步）→ `syncing`（同步中）→ `ready`（就绪，显示 commit 前缀）/ `error`（失败，悬停查看原因）
- **同一仓库同一时刻只允许一个同步任务**：同步中按钮禁用，后端也会拒绝重复提交（含数据源定时同步与手动同步竞争的场景）
- commit 未变的重复同步会直接复用已有快照与分析产物，不重复下载

### 2.5 生成 Wiki

「生成记录」区块 → 「生成 Wiki」。每个知识库同时只允许一个进行中的批次。批次阶段：

`pending → preparing`（冻结快照/准备索引）`→ analyzing`（跨仓库分析）`→ planning`（大纲规划）`→ generating`（逐页生成）`→ validating`（引用校验）`→ staged`（候选就绪，等待发布）

进行中可「取消」，失败可「重试」。生成失败或重新生成不影响当前已发布版本，读者始终能看到上一份完整文档。

### 2.6 发布

批次到达 `staged` 后点「发布」，候选页面原子切换为已发布版本。若当前已有发布版本且同名页面被人工修改过，会提示冲突并让你选择：

- **中止**：放弃本次发布，保留现状
- **保留两者**：人工修改的页面保留，其余页面更新为新版本

### 2.7 阅读

与普通 Wiki 相同的阅读入口（目录、搜索、历史版本）。Code Wiki 页面额外提供**代码证据**：

- 正文中的 `[E1]`、`[E2]` 引用可点击，右侧抽屉展示：仓库名 · 文件路径:行号区间、符号名、commit、代码摘录，以及「在 GitLab 中打开」链接
- 页脚「代码来源」汇总本页引用的全部证据条目

### 2.8 代码更新后

代码变更后重复 §2.4 → §2.6：再次同步（拿到新 commit 快照，未变更的仓库自动复用）→ 再次生成 → 再次发布。旧快照不可变，历史发布版本可回看。

## 3. 配置参考

### 3.1 分析引擎（Provider）

「代码仓库」标签页顶部可配置分析引擎：

- **内置引擎**（默认）：驱动镜像内置的 codebase-memory-mcp CLI，无需配置。`WEKNORA_CODEBASE_CLI_PATH` 可覆盖可执行文件路径
- **自定义 MCP**：填写 MCP 服务地址与凭据，保存后点「测试」校验连接与能力是否满足最低要求（缺能力会明确列出缺失项），通过后即可用于同步与生成

### 3.2 环境变量

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `WEKNORA_CODE_WIKI_DATA_DIR` | `/data/code-wiki`（无 `/data` 时为 `<工作目录>/.local-data/code-wiki`） | 快照存储根目录，生产部署应挂载持久卷 |
| `WEKNORA_CODEBASE_CLI_PATH` | `codebase-memory-mcp`（PATH 查找） | 内置引擎 CLI 路径 |
| `WEKNORA_CODE_WIKI_MAX_ARCHIVE_MB` | 2048 | 单仓库归档下载上限（MB） |
| `WEKNORA_CODE_WIKI_MAX_UNPACKED_MB` | 6144 | 单仓库解包后上限（MB） |
| `WEKNORA_CODE_WIKI_MAX_FILES` | 250000 | 单仓库快照文件数上限 |

### 3.3 API

所有接口挂载在 `/api/v1/knowledgebase/{kb_id}/code-wiki` 下：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET / PUT | `/analysis-profile` | 查看 / 更新分析引擎配置 |
| POST | `/analysis-profile/test` | 测试引擎连接与能力 |
| GET / POST | `/repositories` | 仓库列表 / 新增仓库 |
| PATCH / DELETE | `/repositories/{id}` | 更新 / 删除仓库 |
| POST | `/sync` | 触发同步（可指定仓库，空为全部） |
| GET / POST | `/runs` | 生成批次列表 / 创建批次 |
| GET | `/runs/{id}` | 批次详情（含进度与失败原因） |
| POST | `/runs/{id}/cancel` · `/retry` · `/publish` | 取消 / 重试 / 发布 |
| GET | `/evidence/{id}` | 单条证据详情 |
| GET | `/pages/{page_id}/evidence` | 页面证据列表（阅读页侧栏） |

阅读、目录、历史版本沿用既有 Wiki 页面接口。

## 4. 常见问题

- **同步报错「repository is already syncing」**：该仓库已有同步任务在执行，等待完成即可；同步中不允许重复提交。
- **同步报错归档/解包超限**：仓库超过 §3.2 的体积或文件数上限。优先用「排除规则」裁剪大目录，或调大对应环境变量。
- **仓库含符号链接**：快照会跳过链接条目，只保留普通文件，不影响同步。
- **生成批次失败**：批次详情给出失败阶段与原因（常见：模型服务不可用、引擎能力缺失）。修复后「重试」从失败阶段继续；已发布版本不受影响。
- **发布时提示冲突**：上次发布后有页面被人工编辑。选择「中止」保留现状，或「保留两者」让人工修改优先。

## 5. 边界与后续

首版为**手动同步 + 全量生成**。以下能力在后续阶段规划中：自动增量重生成、GitLab Webhook 触发同步、代码问答、代码语义向量检索。详见[实现计划](./CODE_WIKI_IMPLEMENTATION_PLAN.md)的阶段划分。
