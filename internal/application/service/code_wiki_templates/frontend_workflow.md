按以下结构撰写 flow 专题，描述有证据连接的前端操作链路。单纯导入、文件相邻或函数同名不能证明业务时序。

## 一句话说明与流程入口
说明可查证的操作目标、真实路由/组件/事件入口、涉及文件及分析边界。
## 前置条件
分别说明显示、禁用、输入校验和已知上下文；前端条件不能写成服务端授权保证。
## 步骤
步骤表：序号｜页面/组件｜用户操作或自动触发/条件｜执行位置｜输入与来源｜状态变化｜调用接口/事件｜后端 flow｜响应或跳转。
沿真实调用描述触发 → 校验 → 状态 → 请求 → 响应/导航；每条连接须有调用或事件关系依据。并发、异步回调分别描述，不强排成同步串行。
## 页面跳转与参数传递
列页面之间有依据的跳转、条件和参数来源，不把共同调用某接口当作先后流程。
## 前端可见的状态流转
列状态前后值、触发条件、更新位置及 UI 反馈，不推断后端持久化状态机。
## 权限与分支
区分角色权限、显隐、禁用和业务状态条件；角色含义未知时保留原实现条件。
## 分支、失败与取消
按已发现项列条件分支、校验失败、请求失败、用户取消、重复提交防护、loading 清理和可确认的重试/补偿。没有实现依据就说明未知，不能补造处理。
## 跨组件与跨应用边界
描述实际调用方、接收方、通道/方法、载荷及监听清理；没有跨应用实现时不生成主子应用故事。缺少后端源码时流程止于前端请求及响应处理。
后端 flow 只链接已有且有证据匹配的文档；未接入或未匹配就说明缺口，不猜跨系统链路。
## 关联专题
链接已有页面、API 和组件；必要时可附 Mermaid，但图中每条边同样需要证据。
## 待确认
记录断点、无法解析的动态行为和业务含义，不用理想流程补齐实现。
